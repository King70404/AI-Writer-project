## A1-1 模型连接检查（“检查连接”）

- 现状：设置只区分“配置已保存/Key 已保存”，没有独立连接测试，也不显示“连接成功”。
- 目标：作者主动触发、结果绑定配置版本、失败不清除配置。
- 实施要点：
  - 后端在 `backend/src/aiwebnovel/model_gateway/` 增加检查入口（建议 `POST /ai/models/{profile_id}/connection-check`），优先使用服务商不生成内容的接口；只有生成接口可用时，必须返回“将发送一条测试消息，可能计费”的明确状态，作者再次确认后才调用。
  - 结果带配置版本/摘要（地址、模型、Key 版本变化后旧结果失效）；响应和日志不得含 Key、Cookie、完整地址凭据。
  - 若实际发出模型请求，必须走 B1 用量台账（新操作类型）并按 B2 预算规则处理；仅服务商元数据探测不写台账、不计费。
  - 前端在 `frontend/src/features/workbench/` 的模型设置中分开显示“配置已保存 / Key 已保存 / 连接已验证（版本）”，并提供“检查连接”与失败原因；未验证时不得显示“连接成功”。
- 验收：无 Key、401/403、超时、DNS/证书失败、成功五种结果均可区分；修改地址/模型/Key 后旧结果失效；失败不丢配置；生成测试路径必须经作者确认。
- 测试：后端契约与失败分支；前端状态机；页面无自动探测请求（浏览器网络审计）。

## A1-2 “保存规划并准备”合并动作

- 现状：规划未保存时，作者需要先保存规划、再回到“生成”准备续写，容易漏保存或重复输入。
- 目标：一个明确动作完成“保存规划 + 打开发送准备”，失败时状态可恢复。
- 实施要点：改 `frontend/src/features/novel-structure/components/AIWorkflowAssistant.tsx` 与工作台助手；无未保存修改时保持现有“准备”；保存失败停留并保留草稿；准备失败时规划已保存，可重试准备；不自动发送、不新增模型调用。
- 验收：有/无修改、保存成功/失败、准备成功/失败组合均正确；不发请求仅做准备的路径零模型调用。
- 测试：组件交互测试；必要时补 E2E 断言（不自动采用、不自动发送）。

## A1-3 窄屏抽屉式助手

- 现状：`<1280 px` 默认正文优先，窄屏没有可用的助手入口。
- 目标：窄屏下以抽屉打开准备/生成/评审助手，保留编辑器和助手状态。
- 实施要点：改 AppShell/写作台布局与 `frontend/src/styles/global.css`；抽屉支持打开/关闭、`Esc`、焦点进入与返回、背景滚动锁定；切换时不要重挂载编辑器或丢失未保存正文；桌面宽度行为不变。
- 验收：360/390/768/1024 px 无横向溢出；打开/关闭不丢正文和助手草稿；键盘可达；不发模型请求。
- 测试：前端布局/交互测试；可用现有 E2E 增加窄屏视口检查，但不降低既有断言语义。

## A2-1 首页全书架汇总

- 现状：首页“继续写作”只对最近一本小说显示紧凑汇总，没有全书架统计。
- 目标：书架/首页按作品显示真实字数、章卷数、状态分布与待办数量，一次请求取回，不显示无数据支撑的数字。
- 实施要点：在 `backend/src/aiwebnovel/workbench/`/workspace 汇总服务增加按项目的聚合读模型（如 `GET /workspace/overview`），服务端按非空白字符统计，分页/上限明确，只返回统计与标识、不返回正文；前端首页与书架复用该数据；零模型调用。
- 验收：多小说、空小说、超长小说、删除中的项目；数字与单项目 workspace 接口一致；无 N+1 请求；不返回正文。
- 测试：后端聚合与分页/边界；前端渲染与空态；性能基线不因项目数线性退化到不可接受。

## A2-2 统一待办扩展

- 现状：统一待办只派生 6 类已持久化事项，不含到期伏笔与预算提醒。
- 目标：在不引入新事实源的前提下，把 C 的到期伏笔与 B2 的预算警示纳入统一待办（固定排序、可跳转、不重复）。
- 实施要点：改 `backend/src/aiwebnovel/workbench/` 的待办派生，读取 `story_control` 的到期伏笔与 `usage` 的预算状态；新增类型必须有稳定排序与去重键；不把“计划”冒充事实；零模型调用；前端面板增加类型筛选/链接。
- 验收：到期/未到期/已放弃伏笔；off/warn/strict 预算；同一事项不重复；跳转定位正确；待办接口不返回正文。
- 测试：后端派生矩阵；前端类型与跳转；与 A2 既有 6 类回归。

## B-1 旧 `/ai/continue`、`/ai/rewrite` 计量与预算

> 状态（2026-11-05，分支 `codex/b1-legacy-metering`）：已实现。两个旧接口改走工作流的网关 provider，按 `generation` 归属写入用量台账，并受 B2 预算约束（strict 拒绝不发送、不写台账）。台账不可用时拒绝发送（503 `AI_USAGE_LEDGER_UNAVAILABLE`），不再出现未计量的请求。响应字段保持不变；未配置默认模型仍返回 503 `AI_PROVIDER_NOT_CONFIGURED`。测试：`tests/backend/test_legacy_ai_metering.py`。已通过 Windows 门禁并经 PR #40 合并，详见 `docs/B1_WINDOWS_GATE_20261106.md`。

- 现状：`backend/src/aiwebnovel/ai_writing/web.py` 的两个旧接口仍不写 B1 台账、不受 B2 预算约束。
- 目标：旧接口与新流程同一套用量/预算规则，同时保持响应兼容。
- 实施要点：发送前开账、结束结算（完成/失败/超时/中断），token 只取服务商响应；严格预算在同一事务检查并以 409 `AI_BUDGET_REFUSED` 拒绝且不发送；不重复计量（不要与 workflow 层双开账）；旧客户端响应字段不变。
- 验收：成功/失败/超时/未知用量；strict 拒绝零请求；台账只增不改；与新接口合计口径一致。
- 测试：后端契约、预算与台账一致性；现有旧接口回归；零实际网络请求（假模型）。

## B-2 范文分析/一致性评审发送前预估界面

- 现状：只有正文生成在界面显示发送前预估；分析与评审的预算只在服务端执行。
- 目标：所有会发模型的作者动作在发送前显示保守上限与预算结论。
- 实施要点：后端把预估扩展到分析/评审任务类型（复用 `GET .../runs/{run}/estimate` 或按操作返回），输入按 UTF-8 字节、输出按模型配置上限，明确“上限不是账单”；前端在范文分析与一致性评审的确认区展示预估，strict 禁用发送、warn 需勾选确认；服务端仍二次校验。
- 验收：三类操作一致；strict/warn/off 三种预算；拒绝时无请求、无台账；未知价格标为“未计价”。
- 测试：后端预估契约与预算拒绝；前端交互；E2E 至少覆盖一类非生成操作。

## B-3 缓存 token 计价

- 现状：价格只有输入/输出两项，服务商报告的缓存命中/写入 token 未单独计价。
- 目标：作者可填写可选缓存价格，实际费用按服务商报告的缓存明细计算，未知不按 0 计。
- 实施要点：`backend/src/aiwebnovel/usage/` 的用量模型捕获 OpenAI 兼容 `usage` 中的缓存明细（如 `prompt_tokens_details.cached_tokens`，以实际响应为准）；`model_price_revisions` 新增可选缓存价格（迁移 `0014`），版本化、不预置、不换汇；发送前预估保持保守（不假设缓存命中）；前端价格表单与费用展示分开“报告/估算/未确认”。
- 验收：有缓存明细/无明细/格式异常；缓存价未填时按输入价或明确未计价（按设计定稿）；旧价格版本不回溯；导出 CSV 含缓存列（与 B-4 联动）。
- 测试：后端计价矩阵与迁移；前端表单；不改变既有非缓存计价结果。

## B-4 用量与费用 CSV 导出

> 状态（2026-11-05，分支 `codex/b4-usage-csv`）：用量部分已实现。采用前端方案：用量面板「导出 CSV」按现有 `/projects/{id}/usage` 分页（每页 100）收集，上限 5000 条，超过则拒绝并提示按章节筛选，不截断。UTF-8 BOM、中文表头、未知值写“未知”而非 0、单元格公式中和，不含正文、Key 或地址。单价、币种、逐条金额及缓存列已随 B-3 / PR #46 合入；原用量导出证据与新费用扩展证据分别记录。测试：`tests/frontend/usage-csv.test.tsx`。

- 现状：用量面板只能查看，不能导出。
- 目标：作者可导出无正文、无密钥的用量/费用 CSV，便于自己核对。
- 实施要点：后端建议 `GET /projects/{id}/usage/export.csv`（或前端由已取数据生成，二选一并写清边界），列含时间、章节、操作、模型、报告/未知/估算 token、单价与币种、金额或“未计价”；UTF-8 BOM 便于 Excel；不导出正文、Key、地址凭据；只对同币种合计，不换汇；分页/上限明确。
- 验收：中文表头与编码；未知/未计价/多币种；大数据量不一次性加载全部正文（本来就没有正文）；下载不触发模型调用。
- 测试：后端导出契约；前端下载；CSV 内容断言（含无秘密字段）。
