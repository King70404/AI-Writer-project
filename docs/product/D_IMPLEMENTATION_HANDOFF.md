# D 阶段实现交接：资料导入、外部候选、跨章任务

更新：2026-10-26。事实基线：main `2bf3295`，A1–C 已合并（PR #35）。本文是可领取的实现规格，**D 尚未实现**。遵循作者要求：高开发量功能先设计并推送，由后续 AI 实现。本文不会调用模型、导入作者正文或创建后台任务。

## 交付顺序

| 包 | 作者得到的结果 | 开发量 / 模型调用 | 完成后立即同步 |
| --- | --- | --- | --- |
| D1 旧稿导入 | TXT/Markdown/粘贴 → 分章预览 → 新小说 → 打开第一章 | 大 / 0 | 解析、事务、页面、受影响测试、证据 |
| D2 外部 AI 交接 | 选来源 → 导出 → 导入返回 → 对照 → 明确采用 | 大 / 软件内 0；外部费用不统计为免费 | 快照、候选、采用、页面、测试、证据 |
| D3 跨章任务清单 | 选章节 → 任务清单 → 手动进入当前步骤 → 生成/采用 → 下一章 | 大 / 只在作者确认发送后发生 | 持久任务、run 关联、额度、恢复、页面、证据 |
| D4 自动章节候选 | 单章有界多段组装、局部重做 | 很大 / 高 | 后置，另立候选类型与预算契约 |

D1 最先实施，不等待 D2/D3；D2 不依赖 D1。D3 依赖已存在的 B2 预算及 C 召回，不依赖自动导入记忆或语义索引。每包必须前后端闭环，不交空按钮。完成一个包即提交并推送，不将三包积攒到最后。

## D1：旧稿导入为新小说

### 页面与流程

书架新增“导入旧稿”，打开三步面板：选择文本 → 检查分章 → 确认导入。粘贴和文件输入共用一套服务端解析规则。显示文件字节数、编码、章节数、正文总字数、未归类段落；“确认导入为新小说”只在所有内容都有归属且未超限时可用。

首版只接受 UTF-8（可带 BOM），文件类型仅 TXT/Markdown，最大 10 MiB、500 章。章节正文仍受当前正文契约约束，不能通过导入绕开已有上限。Markdown 原样作为文本，不执行 HTML、不抓取图片链接。没有章节标题时默认一章；提供固定标题格式选择和手动拆分/合并，禁止任意正则。

“第 N 章”、Markdown 一级/二级标题只作候选分界；卷标题需作者明确选择卷，不因出现“卷”字自动丢弃正文。前言、空章、重名标题、尾段都显示。预览保存每个源片段的归属，保证除了 BOM 和作者明确确认的标题包装之外，没有未展示的丢失或重排；保留换行，不自动润色、去空白或归一化字符。

取消预览不创建小说；关闭后可从同一未过期预览继续。确认完成后打开第一章，另提供“查看全书结构”，不得自动提取记忆或调用模型。

### 建议持久化与 API（均待实现）

| 对象 / 端点 | 约束 |
| --- | --- |
| ImportPreview | 服务端 ID、源字节哈希、解析器版本、源文本、受控分章清单、preview_version、创建/到期时间；本地数据库保存，不写业务日志 |
| POST /imports/preview | 文件字节流或粘贴入口各有明确 Content-Type；读取前限制累计字节数，严格解码；请求不得指定服务端文件路径 |
| PUT /imports/{id}/preview | expected_version + 受控分界调整；校验所有范围不重叠、不遗漏、不越界；成功产生新预览版本 |
| POST /imports/{id}/commit | preview_version + 服务端确认的源哈希 + idempotency_key + 新小说名称；只新建，不接受已有 project_id |
| GET /imports/{id}/receipt | 只读恢复结果；访问控制与删除小说契约照旧，不能成为读取已删除正文的旁路 |
| ImportReceipt | 唯一幂等键、规范请求哈希、preview_id/version、创建的小说/卷/章 ID；不重复复制正文 |

预览建议 24 小时有效；过期确认返回 409 `IMPORT_PREVIEW_EXPIRED`，重新预览不创建小说。清理只删除未提交的过期预览，已提交回执保留以支持跨进程重试。删除小说后回执不能重建该小说；只返回已删除状态。

commit 单个数据库事务完成项目、卷、章、正文初始版本和回执。不能循环调用会各自提交的现有 HTTP API。可重用领域校验和仓储，但必须让一个 unit of work 控制事务。任意一章失败整体回滚；不能先建半本再补偿删除。并发重复提交通过唯一约束竞争，失败者读取同一回执；相同幂等键搭配不同请求返回 409，不覆盖回执。

### 必过样例

- BOM/无 BOM、多字节字符、CRLF/LF、空行、序言/卷标题/尾段、空章、同名章；原文片段逐字对账。
- 非法 UTF-8、边界多字节截断、10 MiB 两侧、500/501 章、正文上限两侧；拒绝带明确位置，不静默截断。
- 注入中间章失败，无新项目/卷/章残留；重复提交、两窗口竞争、提交成功但响应丢失、重启后查回执均只得到一份小说。
- 预览版本冲突、过期、修改幂等键载荷、已删除小说；导入全过程捕获模型请求数为 0。

## D2：把选定任务交给外部 AI，再接回候选

### 页面与流程

写作助手新增“外部 AI 交接”，与软件内“发送并生成”分开。第一步选择任务类型、来源及用途，显示实际文本与省略项；第二步“确认并下载交接包”；第三步选择已保存交接任务，上传返回 JSON 或粘贴文本，显示来源为“作者导入的外部候选”，对照后单独采用。

默认不选整书正文、范文原句、其他小说资料。作者从当前章节正文、规划、已确认规则和事实中显式勾选；未勾选的内容不能被上下文构造器顺带补入。显示来源版本与每项字数，服务端仍执行上下文预算。软件只下载文件，不自动打开外部网站或上传。页面提示“外部服务是否计费由该服务决定，本软件未收到其账单”，不能把零软件调用写成免费。

### 快照、返回与采用

- `HandoffSnapshot` 只追加：本地 ID、项目/章节、操作类型、正文与规划基线、实际选中来源版本、输出限制、格式版本、服务端规范化上下文 SHA-256。快照是权威；包内 manifest 可被编辑，不是权限凭证或签名。
- `POST /chapters/{chapter_id}/handoffs/preview` 返回可读预览；`POST .../handoffs` 明确确认后保存不可变快照；`GET .../handoffs/{id}/download` 生成固定文件名 `task.md`、`context.json`、`manifest.json`。无用户指定 ZIP 内路径，无配置/Key/内部日志。GET 不创建新任务。
- `POST .../handoffs/{id}/candidates` 必须绑定本地快照，JSON 先检查 256 KiB 上限再解码解析，拒绝重复/未知字段；纯文本入口明确 Content-Type 和同等字节限制，操作/归属/基线均来自本地快照。
- 返回 JSON v1 只接受 `format_version`、`handoff_id`、`context_sha256`、`text`；首版不接收批量事实建议或自动执行指令。长度使用快照声明的**候选类型**上限，不能拿 256 KiB 当正文上限。复用逐段候选时仍为 200–300 个非空白字符；整章候选不是本包范围。
- `ExternalCandidate` 保存 snapshot_id、载荷哈希、不可变文本、状态、来源标识；重复导入相同快照/载荷返回同一候选，不能产生重复采用。不得伪造 provider usage、模型请求或成功账单；来源始终是 external_import。
- 导入阶段身份/哈希不符拒绝。合法快照但本地来源已变：候选可保存为“待重新核对”，不能采用；重新准备产生新的快照，不把旧基线偷偷改成当前版本。
- 采用调用统一正文写入领域事务，校验当前正文、规划及所有约定来源版本；绑定幂等回执。已采用重试返回同一回执；正文冲突保留候选供查看/下载，不覆盖。引用的小说/章被删除时禁止导入和采用。

### 必过样例

拿错小说/章节、未知快照、哈希不符、伪造 manifest 基线、规划/事实/正文变化；超长、重复 JSON key、未知字段、非法编码、空文本；重复上传与双击采用；下载文件中无 Key 和未选文本；文本内伪造系统指令不能改变采用权限。模型调用数为 0，TXT 导出在作者采用前不变。

## D3：跨章任务清单，作者逐步推进

### UI 与状态

结构页增加“安排写作任务”，选本书最多 10 章、顺序、每章目标场景/规划版本、模型和步骤/输出上限。确认只创建清单，不准备所有上下文、更不发送模型。任务抽屉显示当前章、已采用段数、剩余请求额度、最近失败、费用状态；只为当前步骤提供“保存正文并准备”，复用现有发送预览、费用确认、候选对照和采用按钮。

采纳后提供“继续本章”或“结束本章任务并进入下一章”。结束表示本次工作计划完成，不等于章节定稿；即使全部任务完成也不自动修改 A2 定稿状态。切到下一章时读取最新正文/事实/规划并重新冻结上下文。关闭页面/重启只读恢复清单，不触发发送。

| 当前状态 | 作者动作或事件 | 结果 |
| --- | --- | --- |
| planned | 准备当前步骤 | 校验当前依赖，创建并绑定一个现有 workflow run，ready |
| ready | 确认发送 | 在既有预算预留与发送权事务内计数，running |
| running | 收到有效候选 | waiting_author；不自动发下一段 |
| running | 失败/超时/启动发现未结算 | failed/interrupted；未知费用保持预留 |
| waiting_author | 采用 | 以采用回执推进已采用量；可继续准备，或由作者结束本章 |
| 任意非终态 | 暂停 | 禁止新发送；已发请求可能仍计费，返回候选保留 |
| paused/failed/interrupted | 恢复/重试 | 先检查任务与来源，显式确认；重试占用新的请求与费用额度 |
| 任意非终态 | 终止 | cancelled；保留已发请求、候选、采用回执，不自动补发 |
| 所有步骤作者结束 | 完成 | completed；未采用候选仍可查看，不自动写正文/事实 |

### 编排契约

新增 `WritingJob`、`JobStep` 与追加事件/回执。任务自身要持久化，不以浏览器 localStorage 为权威。每个步骤绑定一个本书 chapter_id；同章去重，不能通过客户端嵌入另一本书的 ID。并发控制使用 expected_version；一个 job 同时至多一个进行中的步骤。

建议接口：`POST/GET /projects/{id}/writing-jobs`，`GET /writing-jobs/{id}`，`POST /writing-jobs/{id}/prepare-step`，`POST .../pause`、`.../resume`、`.../cancel`、`.../finish-step`。发送/采用继续使用 [现有 workflow 路由](../../backend/src/aiwebnovel/ai_writing/workflow_web.py)，但必须在服务端识别关联 job；不能只在新按钮检查额度，而让原 generate 路径绕过总限额。run 创建与 step 绑定要原子或具备可恢复唯一操作键，双击不能产生游离重复 run。

- 首版每章至多沿用既有 10 步/3000 字上限，任务总发送上限建议 10 次（包括显式重试），任务总输出上限建议 3000 字；数值是拟实施限制，不是现有跨章能力。模型请求开始前事务预留，两个窗口不能同时扣最后一个名额。
- 任务额度、B2 单次/月费用预算同时满足才允许发出；所有用户入口遵循同一检查。D3 不调用未计量的旧 `/ai/continue` 或 `/ai/rewrite`。
- 生成字数、作者编辑字数和正式采用字数分别记录。B2 允许作者扩写候选，不能将手工扩写错误计为模型输出；已丢弃候选也不退回已消耗请求/费用。
- 换模型/预算/规划只影响新的准备，旧候选保留原模型与版本。源章或固定事实失效时拒绝发送旧依赖；不能仅在页面出现提示但服务端照发。
- 重复 adopted 回调不推进两次；以现有采用回执 ID 唯一约束关联，禁止前端自行上报“已采用”。
- 暂停/取消与正在发送存在竞态：发出前取消不得调用服务商，发出后取消不得承诺退款；返回结果入账并保留，绝不调度后续步骤。

### 必过样例

创建清单/页面刷新/重启/切章无请求；双击准备只有一个 run；双击发送只有一次请求；并发抢最后额度只有一次成功；直接调用原 generate 也受 job 额度约束；预算不足请求数为 0；超时和重试各有真实 attempt；断电恢复 interrupted；取消保留候选并阻止新发送；采用回执重放不推进两次；下一章上下文引用最新已确认事实而非上一章旧快照。
