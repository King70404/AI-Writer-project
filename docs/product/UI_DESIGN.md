# 界面设计：让写作成为主界面

2026-10-22 · **设计规格，尚未接入正式应用**。对应交互样稿：[ui-prototype.html](ui-prototype.html)。样稿中的小说、模型、任务、备份均为演示数据；刷新即重置，没有模型调用、正文保存或数据库操作。

原型覆盖书架、写作生成子流程、范文对照、模型/费用示意与备份恢复示意。右侧完整的准备/生成/评审分区、工作台汇总与冲突处理以本文及流程规格为准，尚未全部做成可点界面；原型里的续写/改写/构思是生成子流程的操作示意，不代表所有新任务类型已存在。

## 1. 方向与问题依据

当前 `AppShell.tsx` 将“工程基础”列为首个入口，`FoundationPage.tsx` 首屏展示“前端基础已启动”和系统状态。`ChapterWritingPage.tsx` 在正文后串接 `AIWorkflowAssistant`，范文、规划和记忆又嵌入助手。这适合验证模块，却让作者找功能、翻长页面、判断下一步的成本很高。

新版以**书架 → 小说工作区 → 章节写作**为骨架。视觉采用纸白、墨色与低饱和森林绿，保持安静、清楚、有文字密度。正式产品名称继续使用“AI 网文助手”，不再用 RF 编号、V1 阶段牌、工程健康报告占据作者首屏。

设计验收看三件事：正文读起来舒服；当前状态可信；下一步操作容易找到。换颜色而保留原来的长表单堆叠不算完成本设计。

## 2. 信息架构与现有路由对照

| 区域 | 作者看到的内容 | 实施边界 |
| --- | --- | --- |
| 书架 | 最近编辑的小说、继续写作、新建小说；空书架有明确起点 | 复用 `/projects`；将 `/` 变为作者入口是后续实现，原工程状态移入系统信息，更新精确路由测试 |
| 小说工作区 | 左侧卷章树；设定人物、范文方法、故事记忆的固定入口 | 保留 `/projects/:projectId` 和已有子路由；布局重组不另建一套业务实体 |
| 章节写作 | 正文、保存状态、章节目标；右侧准备/生成/评审切换 | 复用 `/projects/:projectId/chapters/:chapterId/write` 及现有 hooks/API |
| 范文研习 | 原文和分析对照；编辑、确认方法；选用到章节 | 复用 `ReferenceWritingWorkbench`；独立展示页为后续前端路由，数据仍属当前小说 |
| 故事资料 | 设定、人物、已确认事实及待复核项 | 先复用现有模块；时间线、伏笔与关联视图见功能规格，未实现前不画成可用导航 |
| 模型设置 | 添加/编辑配置、当前选用状态；有需要才展开高级项 | 复用 `AIModelSettings`，设置入口跨页面可达；“费用”只在账本实现后显示真实数值 |
| 备份与恢复 | 最近备份、校验结果、下载、恢复副本 | 保留 `/backups`；沿用现有 ZIP 格式与新目录恢复边界 |
| 系统信息 | 版本、服务与数据库状态、可复制的脱敏诊断信息 | 从写作首屏移出，故障发生时提供直达入口；不隐藏故障 |

不在本轮先添加未接通的正式页面或导航。HTML 中的页面切换是设计演示，不是路由已实现的证据。

## 3. 布局

### 书架

桌面左侧保留主导航，内容区顶部是“继续上次创作”，下方是小说列表。每本书只显示书名、简介摘要、最后编辑时间和继续入口；字数只有服务端确有统计时才展示。没有真实统计接口时省略，不用虚构数字填空。

新建小说的必填项只保留书名。简介等附加项可展开；设定、人物、模型配置均不阻止进入空白章节。零小说、加载中、失败、删除后空列表分别有明确状态。继续写作记录只存小说/章节标识和时间，不把正文放到浏览器存储；目标删除或无权限时回到该小说结构页。

### 写作台

- **左栏 240 px**：书名与返回书架、卷章树、章节搜索入口。当前章有左侧标线及文字状态；长章名可换行，不只依赖 hover。
- **中栏自适应**：顶部章名与真实保存状态；正文纸面建议最大宽 720 px，编辑时正文区域至少高 60 vh。章目标与本章重点默认一行摘要，可展开。正文不因候选长短跳动。
- **右栏 340–380 px**：准备、生成、评审三个入口，始终只展示当前任务的主要步骤。详细上下文、历史候选、技术诊断逐层展开；阻断原因始终可见。
- 侧栏独立滚动时，必须保留可见焦点且不制造滚动陷阱；整个应用只保留一个主要页面标题。
- 专注模式折叠两侧栏，保留章名、保存状态及退出按钮。`Escape` 可退出；退出恢复原来的章节、选区和面板，不重挂载编辑器而丢失输入。

### 范文研习

桌面双栏：左原文，右侧对应句段的“作用 / 写作原因（推测）/ 可迁移方法”。点分析条目定位并高亮原文；原文多次出现时按句段位置定位，不用全文模糊匹配。底部“编辑并确认方法”单独确认不可变规则版本，然后“用于当前章”。范文原句不默认带入正文生成。

### 模型与备份

模型配置采用摘要列表与单个编辑抽屉，避免设置表单长期挤占写作区。配置已保存、密钥已保存、连接已验证必须是三个不同的状态；当前没有独立连接测试，不显示“连接成功”。更换模型只影响下一份新任务，已准备任务仍显示冻结模型。

备份列表使用紧凑表格/移动卡片：时间、体积、校验状态、操作。列表读到清单不等于完整校验成功。恢复摘要显示目标副本和下一步启动方式，当前数据保持原样；恢复包不包含模型配置和 Key，必须在引导中说明。

## 4. 视觉规格

| 项目 | 设计值 / 用法 |
| --- | --- |
| 页面背景 | `#F7F5EF`；侧栏 `#EFEEE7`；纸面 `#FFFEFA` |
| 主文字 | `#25332E`；次级文字 `#617067`，需用最终组合测对比度 |
| 主色 | `#365849`；只给当前页、主要动作、选中与重点，不给每个区块铺色 |
| 边界 | `#DADFD6`，1 px；分组靠留白与细线，少用嵌套卡片 |
| 提醒 | 褐金 `#805A23`；错误 `#A23436`；状态同时有文字，不单用红绿 |
| 圆角 | 控件 6–8 px，主要容器 12 px；不用所有元素胶囊化 |
| 阴影 | 只用于浮层、菜单、少量纸面，静态表单不层层投影 |
| UI 字体 | 系统中文无衬线：`Segoe UI` / `Microsoft YaHei` / sans-serif；不联网下载字体 |
| 正文字体 | 系统可用宋体或作者选择；默认 18 px，行高 1.9，字号可调 16–24 px；编辑器兼容中文输入法 |
| 层级 | 页面标题 24–30 px；区块 18 px；UI 正文 14–16 px；说明不少于 12 px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px；正文段落留白统一 |
| 图标 | 16–20 px 单色线形 SVG；关键动作带文字，不用 emoji 充当导航系统 |
| 动效 | 120–180 ms，只做面板展开/焦点引导；尊重 `prefers-reduced-motion`；不做假进度 |

原型提供主视觉参照，正式组件以可访问性、输入稳定和真实状态为准。不要为“高级感”降低文字对比度或把大段文字做成过小灰字。

## 5. 响应式与键盘

| 可用宽度 | 呈现方式 |
| --- | --- |
| ≥1280 px | 左目录 + 正文 + 右助手；可手动折叠任一栏 |
| 960–1279 px | 正文优先；目录收为可打开面板，助手按需打开；不把正文挤到窄条 |
| 600–959 px | 正文单栏，助手用页内切换/抽屉；切换前保留未保存正文，不隐式提交 |
| <600 px | 顶部导航入口 + 单栏页面；范文原文/分析可切换；表格转条目；主要操作不横向溢出 |

所有控件有中文可访问名称。焦点样式至少 2 px，正文/普通控件对比度 ≥4.5:1；触控主要操作建议 44×44 px。抽屉/对话框正确管理焦点、`Escape` 和返回原触发按钮。200% 缩放后仍能读到错误、保存状态与确认操作。章节编辑器保留现有 `Ctrl+S`；新的快捷键不得抢中文输入法组合键，专注快捷键可由用户关闭。

## 6. 状态组件与禁止混淆

| 场景 | 必须看到 | 可做的下一步 |
| --- | --- | --- |
| 正文未保存/保存中 | 真实状态；失败时保留当前输入 | 重试保存；失败不得以切换界面掩盖 |
| 当前没有模型 | “手动写作可继续”；添加模型入口 | 原地添加，成功返回并选中 |
| 请求已发出 | 生成中、实际模型、本轮编号 | 等待或暂停后续；不声称已撤销正在外部执行的请求 |
| 请求中断/超时 | 本次结果尚未确认，可能已计费 | 先查已有任务；作者明确决定是否新请求；不自动重发 |
| 有候选 | 与原文区分的候选面板、长度、来源任务 | 采纳、丢弃；正文变化时先处理版本冲突 |
| 规则/记忆过期 | 来源章与旧版本、需复核原因 | 查看原文、重新评审或人工修正；不静默当作事实 |
| 成功状态 | 服务端已确认的成功消息 | 临时提示辅助；关键状态在页面持续存在 |

不把“本轮任务已完成”解释为“章节已完成”；不把字数当 token；不把估算费用当供应商账单；不把恢复目标展示成功当作副本已启动。原型中的“演示”状态必须在正式接线时替换为真实状态机，不能把样例数据带入产品。

## 7. 实施拆分与视觉完成定义

1. **先落地外壳和书架**：修改 `AppShell`、`FoundationPage`、项目页和样式 token，保留现有数据 API。同步更新路由清单与导航断言。
2. **再整合写作台**：把现有准备、范文、模型、记忆组件放入可切换面板；保持 hooks 生命周期、候选状态、正文 revision 校验。首版不引入富文本编辑器或新状态管理库。
3. **再落地差异比较、候选编辑等功能**：按 [功能设计](FUNCTION_DESIGN.md) 新增相应数据契约，不能用 CSS 或可编辑文本框冒充已持久化。

交付要验证：1440/1024/768/390 px，书架、空状态、写作、范文、设置、备份；200% 缩放；键盘完成配置→预览→确认→采用；中文连续输入无焦点跳动；生成中切换面板不重发；刷新读取既有任务；失败/冲突显式可见；正文与 TXT 导出保持一致。按仓库规则执行受影响检查及一次最终完整 IncludeE2E，沿用有效旧证据而不重复空转。
