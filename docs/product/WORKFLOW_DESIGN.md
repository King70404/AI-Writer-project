# 作者工作流程优化设定

更新：2026-10-22。状态：**设计待实现**。以本轮设计分支的产品代码基线 `57ed00f` 为依据；本文件没有改变产品行为，也不把交互原型当成功能交付。

目标：作者始终知道“我在写哪章、什么已保存、AI 有没有真正发送、结果在哪里、下一步能做什么”。优先缩短寻找入口、滚动和重复录入；保留向模型发送内容、采用正文、确认事实与规则的作者决定。

## 1. 现有能力与真实摩擦

以下是源码检查结果，不是重新报告历史缺陷，也不是作者正式数据的使用记录。

## 2. 作者工作的主路径

### 2.1 工作台进入章节

现在：项目 → 小说详情/结构 → 找章节 → 进入正文 → 滚到 AI 区。

设计：工作台的“继续写作”卡展示小说、最后章节、最近已保存时间；点击直达该章。章节页固定显示小说/卷/章、保存状态、字数与任务状态。左侧为卷章导航，中间为正文，右侧为当前助手；具体尺寸和视觉样式由 UI 设计文档统一。

- 首次进入无小说：主按钮“新建小说”，可选“查看示例流程”；示例必须标为演示，不接真实模型，不写入作者项目。
- 已有小说：主按钮“继续写作”，次按钮“查看全部小说”。不主动发起任何模型分析。
- 没有最近章节：定位小说结构，主按钮“新建章节”。历史记录仅用于定位，不能覆盖服务端章内容。
- 章节切换前有未保存内容：先尝试本地服务保存；失败保留原章并给出“重试保存”“先保存本地副本”。不得仅关闭面板后丢失内容。
- 工程诊断移到设置的“运行状态”；保留维护入口，不作为作者默认首页。

### 2.2 首次配置模型

现在：在章内展开配置 → 手填 → 保存 → 模型已自动选中。

设计：空模型状态卡只有一个主动作“添加模型”；打开模型设置抽屉，默认显示基础字段，保存后回到原章节并选中新配置。已有模型时顶部显示“当前模型 · 配置状态”，提供“切换”和“管理”。管理页与章节抽屉复用同一数据层。

表单分成“显示名称”“服务位置”“基础地址”“服务商模型 ID”“API Key”；Token 上限归入“输出设置”，仍可在发送摘要中看见。提供可维护的服务商填写模板，但模板不等于通过连接测试，不能把某个模型名称硬编码为永久有效。

| 状态 | 面向作者的文字 | 可执行动作 |
| --- | --- | --- |
| 未配置 | 添加模型后即可准备 AI 任务 | 添加模型 |
| 校验未通过 | 在字段旁说明缺项或格式问题 | 聚焦第一个无效字段 |
| 保存中 | 正在保存模型配置… | 阻止重复提交，保留输入 |
| 保存成功 | 配置已保存，已选中“配置名称” | 返回写作；可选检查连接 |
| 云端缺密钥 | 配置已保存，还需填写 API Key | 补充密钥 |
| 保存失败 | 模型配置未保存：具体可行动原因 | 保留非秘密表单，重试；密钥按现有安全策略处理 |
| 需要升级 | 需要启用 AI 协作，正文可继续写 | 复用“备份并启用 AI 协作”及已有升级契约 |

“检查连接”是独立后续能力：优先使用不生成内容的服务商接口；若服务商只支持生成测试，必须明确“发送一条测试消息，可能计费”，作者确认后才调用。没有成功实测前只能显示“配置已保存”，不能显示“模型正常”。检查结果应绑定配置版本，改地址、模型或密钥后旧结果失效。连接检查失败不抹掉已保存配置。

### 2.3 正文生成与改写

常规续写的动作链保持三次有意义的点击：**准备续写 → 确认发送并生成 → 追加到正文**。云端发送保留内容范围同意勾选。后续章节已具备模型和已保存规划时，不再次要求填写首次配置步骤。

1. 编辑区边缘有“准备续写”；选中非空正文时出现“改写选中内容”。当前“续写”按钮改为更准确的“准备续写”。高级项里设置本轮段数和额外要求。
2. 准备前检查正文、规划保存状态。正文沿用现有 `flush()`；规划未保存时显示“保存规划并准备”，明确此动作只保存与准备，不发模型。保存或版本校验失败则停在原地，不能继续创建任务。
3. 准备成功打开固定位置的发送摘要：模型/服务地址、操作类型、选区、采用资料与遗漏数量、输出上限、任务准备时的正文版本。完整内容可展开；摘要不能暗示仅发送可见简述。
4. 作者确认发送后即时进入“正在发送请求，等待模型回复”。按钮变为不可重复点击。请求未返回时显示已耗时和可操作的状态说明，不编造百分比、剩余时间或服务商是否已经扣费。
5. 生成完成后右侧进入候选页，正文保持可见；续写显示插入位置，改写显示原段/候选并排及本地差异标记。
6. “追加到正文”或“替换选中文本”是主动作；“丢弃候选”为次动作。采用后显示保存状态与当前版本。“采纳并生成下一段”单独说明将再次发送并可能计费，沿用本轮已授权范围；不得默认触发下一段。

模型切换只作用于下一次新准备的任务。旧任务继续显示其模型快照，提供“用当前模型重新准备”，不能在旧任务上悄悄替换模型或扩大发送范围。

“暂停后续生成”应准确命名：现有暂停不保证取消服务商正在执行的请求，不能把它显示为“取消扣费”。如果未来新增流式中止，也必须区分本地停止接收与服务商终止执行。

### 2.4 范文 → 写作规则 → 章节

现在：长工作台内保存范文 → 发送 → 分析 → 载入规则 → 编辑确认 → 找规划勾选规则 → 保存规划 → 回到任务。

设计为四个可返回的阶段：“范文”“对照分析”“写作方法”“应用到本章”。进度来源于已保存对象状态，不以“点击过下一步”表示完成。

| 阶段 | 默认呈现与主动作 | 保留的决定 |
| --- | --- | --- |
| 范文 | 粘贴、名称、句/段粒度；显示字符数和已保存样本；主动作“保存并预览分析内容” | 保存不发模型；长范文不自动切块连发 |
| 对照分析 | 左列原句/原段，右列写作作用、推测原因、可迁移方法；定位对应文本；主动作“提炼写作规则” | “写作原因”始终标为文本推测，不能当作者真实意图 |
| 写作方法 | 编辑建议规则及适用范围；选择保留项，显示源范文；主动作“确认规则版本” | 新版本不可变，不能自动确认模型建议 |
| 应用到本章 | 显示所选规则版本与本章重点；主动作“将此规则加入本章规划” | 明确修改哪些规划字段，保留原选择及未保存修改，版本冲突时不覆盖 |

“加入本章规划”之后应直接看到已选规则和保存状态；可提供“保存规划并准备续写”，不再要求作者在长列表里找刚确认的版本。只把确认规则加入生成上下文，范文原句不自动注入正文。

重复打开已有分析、搜索原句、筛选规则、比较版本、把规则加入本章均为本地操作；不再调用模型。分析结果与原范文版本、模型快照绑定，改范文需新建分析任务，不能复用成“新内容已分析”。

### 2.5 写完本章与维护长篇记忆

章节助手与 UI 设计统一分为“准备”“生成”“评审”三个顶级面板。“准备”内有章节规划和范文方法入口；“生成”处理发送预览、任务和正文候选；“评审”处理长篇记忆、事实确认及一致性建议。页面默认不同时展示全部表单。

写到章末时提供可跳过的“本章收尾”卡：

1. 检查正文已保存，列出本章目标和当前字数；这不调用模型。
2. 展示现有待确认事实与待处理评审建议，可直接逐项处理；不要自动重新评审。
3. 作者需要新评审时点“准备一致性评审”，查看范围后“确认发送并评审”。是否达到文学质量目标不由保存成功或字数达标代替。
4. 处理候选事实，展示原文引文、来源章、版本。确认、编辑后确认或驳回；缺有效来源、已过期、版本不一致者不得一键确认。
5. 处理修改建议，可“定位原文”“准备定向改写”或保留。原文已改变/引文多处重复时不猜替换位置。
6. “进入下一章”只导航或创建草稿，不自动生成正文，不把未处理建议当已完成。

记忆面板优先显示“需要我处理”：来源过期事实、待确认事实、待处理建议及受影响章节。历史确认记录和召回详情为可筛选列表，默认折叠。项目级队列必须保留章节归属，不能跨小说共享事实。

召回摘要继续显式说明预算及遗漏：现有最多 24 项/10000 字符；“没有列出冲突”不等于“全书无矛盾”。本轮只是重排与解释；扩大召回、嵌入检索、多轮评审属于后推的重功能。

### 2.6 备份、下载与恢复后继续写作

现在：数据备份 → 立即备份 → 下载/校验 → 填副本名并确认 → 恢复成功文字说明。

设计：顶部卡显示“最近备份时间、包含多少小说和章节、是否已校验”。正文未保存时先说明备份只包含已落盘数据；从章节进入备份先保存，失败不跳过。全局备份页不能声称已捕获其他浏览器页尚未保存的文字。

- “立即备份”保留为一个动作，完成后自动校验，不增加重复确认。
- 创建成功主动作“下载此备份”，次动作“查看清单”；清单只列数据类型/计数，不泄漏正文与秘密。
- “恢复为独立副本”显示源时间、章节数、副本名称和当前不会改变的目标范围，沿用现有一次确认。
- 恢复成功提供经过后端确定的副本标识/路径、可复制的启动命令、需要重新配置模型的说明，并明确当前仍在原数据根；命令按 PowerShell 参数规则正确转义，不能拼接未经校验的用户文本。
- 不伪装“一键打开副本”：当前浏览器没有可验证的启动器能力。先交付复制命令与步骤；未来做本地启动器时再增加“打开副本”，须验证新进程端口/数据根并显示醒目标识。
- 后续实现持久恢复记录：刷新后仍可查看自己的已成功恢复副本及启动信息；刷新只读记录，不再次执行恢复。仅记录系统管理的副本，不扫描作者任意目录。
- 不把模型配置/Key 包含在备份中；这是本基线实际契约，设计不改变它。

## 3. 统一状态和异常处理

界面语言按作者动作解释，后端错误码可在“详情”中复制用于诊断。一个失败显示在对应操作区域，并让屏幕阅读器播报一次；不要同时在页顶、卡片和弹窗重复显示同一错误。

| 状态 | 页面行为 | 作者下一步 | 禁止行为 |
| --- | --- | --- | --- |
| 内容未保存 | 固定状态“未保存”，保留原稿与当前光标 | 保存或继续编辑 | 把准备按钮变灰却不给原因 |
| 保存中 | 显示“正在保存”，继续键入时追踪新修改 | 等待/继续写作 | 用上次保存成功误标新内容已保存 |
| 保存失败 | 错误固定在编辑器边缘；本地文字保持 | 重试保存、保存本地副本 | 跳转、刷新或生成后覆盖本地原稿 |
| 版本冲突 | 显示本地/服务器版本来源；先提供保留本地副本，再比较/选择 | 手动解决，明确确认替换 | 自动使用最后写入覆盖一方 |
| 准备中 | 正文/规划保存完成后创建快照；标“尚未调用模型” | 等待；失败定位具体来源 | 准备自动触发付费模型请求 |
| 待发送 | 同屏显示摘要、同意范围、主按钮 | 确认发送或返回修改 | 改动上下文后沿用旧同意范围 |
| 运行中 | 显示任务类型、模型、已耗时；保留已持久任务入口 | 查看状态、暂停后续生成 | 假进度、重复点击产生并发请求 |
| 响应未知 | “未确认是否完成，先读取任务状态”；只读对账 | 刷新状态，必要时作者重试 | 网络超时自动重发模型请求 |
| 模型报错/空结果 | 区分鉴权、限流、输出截断、协议异常、内容为空；使用服务端已脱敏信息 | 调整配置/内容后重新准备，或显式重试 | 将空白当成功候选；展示秘密、原始异常栈 |
| 候选待处理 | 明确“尚未写入正文”；保持候选与版本依据 | 采用或丢弃 | 自动采用、无声重新生成 |
| 来源过期 | 展示“源正文已修改”，指出受影响对象 | 查看变更、重新准备或复核 | 用旧上下文伪装最新评审结论 |
| 已保存成功但后续读取失败 | 保留成功的对象标识，提示“已提交，正在确认显示” | 只读刷新核对 | 重发保存/采用来试探状态 |
| 会话失效/服务关闭 | 说明当前本地服务连接状态；保留页面草稿 | 重新连接并核对版本 | 删除草稿、重复请求或声称数据已丢失 |
| 页面刷新/重新打开 | 从服务端读取已有任务、候选、分析及评审；重建当前状态 | 继续明确选择的任务 | 自动发送、自动采用、默认为最近任务已获发送同意 |

统一异步按钮规范：触发后立即显示本动作反馈；请求层设置同步互斥锁，不能只依赖 React 下一次渲染禁用；错误不清空必要输入。已有的锁、幂等键和错误后只读对账机制应复用。需新增的重连/状态轮询只允许查询已存在任务，并可停止；刷新不能隐含写操作。

**WF-06 草稿恢复的待实现契约：** 浏览器持久草稿是作者本机的恢复辅助，不是已保存正文；当前页面内保留输入不等于已支持该能力。

- 由后端提供不含路径、无鉴权用途的稳定 `storage_instance_id`，同一数据根正常重启保持不变；复制或恢复为独立数据根时必须重新生成，不能直接沿用备份内标识。草稿键包含该标识、小说 ID、章节 ID 和编辑会话 ID，记录正文基线修订、草稿内容与更新时间；不能只按端口或章节 ID 隔离，多个标签页也不能相互覆盖草稿。
- 作者编辑后有界延迟保存本机草稿，不只依赖关闭页面事件；正文保存成功后，仅清理与服务端已确认内容相同的草稿版本，新输入仍保留。浏览器存储失败或额度不足必须可见，不能显示“可恢复”或静默删除其他草稿。
- 重开时先核对存储实例、章节归属和服务端修订，再提供“比较并恢复到编辑区 / 下载本地副本 / 丢弃此草稿”；即使基线相同也不自动写回服务器。基线变化时保留两份供比较，最终保存仍走现有版本条件。实例不同、章节已删除或无法核对时，不自动套用到同 ID 章节，只允许作者导出或明确清理本机草稿。
- 提供按小说查看和清理本机草稿的入口；未恢复的草稿首版不按时间自动删除。作者主动丢弃，或确认服务器已有相同内容后方可清理。草稿不包含模型密钥、不参与模型发送，也不属于服务器备份；清除浏览器数据会清除它，界面需说明此边界。

## 4. 无障碍与窄屏

- 主区有可见标题与跳转链接；桌面三个区域的阅读顺序固定为章导航、正文、助手。窄屏收为单列，导航和助手作为有标题的面板，返回正文保留选区与滚动位置。
- 不能靠颜色区别保存失败、来源过期和运行中；使用短文字与图标。焦点边框可见，正常文字和操作控件对比度按 WCAG AA 目标验收。
- 面板切换使用真实按钮/链接和明确选中状态。抽屉打开时将焦点移到标题或首项，关闭后回到原触发按钮；有焦点约束的模态才使用 `aria-modal`，不得假模态后让键盘走到遮挡内容。
- 保存、生成完成用 `role="status"`/礼貌播报；必须立即处理的错误用 `role="alert"`。流式正文不逐字朗读；读屏可主动查看生成结果。
- 桌面支持 Ctrl+S，并兼容 macOS Command+S；工具提示不能是禁用原因的唯一载体。当前正文对 Tab 的缩进拦截需提供开关/退出说明，不能让键盘用户困在正文。
- 320 CSS 像素宽不产生整页横向滚动；长地址、文件路径和来源引文可断行。对照分析和改写差异在窄屏按“原文/说明/候选”切换，不能压成两列细条。
- 主动作最小触控区按 44×44 CSS 像素设计；底部固定操作条预留内容空间，避免挡住选区、最后一行正文与移动端键盘。
- 字号、行距、正文阅读宽度是本地偏好，切换不影响存储内容；支持系统减少动态效果偏好，生成中不使用闪动装饰。

## 5. Token、开发范围与交接分工

本表的“额外模型 Token”指产品运行时的模型请求；开发实现本身也有上下文成本。复杂跨模块能力本轮只设计，后续 AI 按任务包实现，不能因当前文档存在而标成已完成。

| 工作包 | 明确交付 | 额外模型 Token | 适合安排 |
| --- | --- | --- | --- |
| WF-01 作者入口与状态条 | 工作台入口、继续写作定位、章/保存/任务状态、动作命名 | 0 | 优先；前端入口与状态展现 |
| WF-02 模型设置与发送摘要 | 共用配置抽屉、成功即选中、缺密钥解释、预览内禁用原因、模型快照说明 | 0；连接生成测试另行显式计费 | 优先；复用现有接口 |
| WF-03 写作布局与候选对照 | 编辑区/助手切换、原文差异、返回定位、键盘/窄屏 | 0 | 布局归 A1，对照归 B1；本地差异算法，不调用 AI 做 diff |
| WF-04 范文规则应用捷径 | 阶段导航、对照阅读、确认规则后加入规划、保存后准备 | 0；已有分析调用次数保持不变 | 下一批；需要跨组件保存协调与冲突测试 |
| WF-05 作者待办与事实队列 | 项目级待处理列表、版本来源、过期筛选、章节跳转 | 0；作者主动发起评审才计费 | 下一批；先定义列表接口与分页，禁止拉全正文 |
| WF-06 保存冲突与草稿恢复 | 本地副本保留、版本差异、本机草稿恢复与清理策略 | 0 | 后推完整实现；涉及数据保护和跨页编辑状态，不当作小样式修改 |
| WF-07 恢复副本可继续使用 | 持久恢复记录、可信启动信息、复制命令、当前数据根标识 | 0 | 后推跨前后端实现；一键启动器另外立项 |
| WF-08 全章/长篇自动流水线 | 分场景预算、暂停恢复、局部重做、每次发送范围与作者采用节点 | 高；规模随章数与重试增长 | 只做设计交接，必须独立预算、真实模型与作者质量验收 |
| WF-09 扩展记忆检索与多轮评审 | 来源可追溯检索、召回预算、增量更新、评审停止条件 | 中至高；嵌入/评审均可能计费 | 只做设计交接；不能拿现有 24 项召回冒充全书覆盖 |

交接给其他 AI 的边界：

1. **前端体验 AI**：先 A1 的 WF-01 基础入口、WF-02、WF-03 布局和 WF-04。只读候选差异归 B1；汇总和作者定稿状态归 A2。复用现有 hook/API，保留发送及采用确认。
2. **写作流程 AI**：A2 的 WF-05，随后 B1/B2 的对照、候选编辑和用量记录。先落组件状态流和必要接口变更，再实现分页和保存协调；规则和事实仍由作者确认。
3. **数据可靠性 AI**：B2 的 WF-06；D 中可独立交付的 WF-07。分别说明临时草稿与服务器事实源、恢复副本与当前数据根的边界，使用自有隔离目录验证。
4. **长篇生成 AI**：C 的 WF-09 先做本地检索，D 的 WF-08 等预算和召回就绪再实施。未经作者指定不读取正式作品和 Key，不自动连续花费预算。

精确范围与依赖以 [交接入口的映射表](README.md#推荐实施顺序每次完成一条作者闭环) 为准，WF 编号是流程索引，不是额外增加的一套排期。

各工作包先读取本文件相关小节、对应源码、当前契约和 `AGENTS.md`；不用全仓历史、旧报告和全量 Issue 评论凑上下文。实现 PR 应列出改变的作者路径、必要数据契约、未实现项及真实验证结果。

## 6. 可验收的流程定义

以下是未来实施验收条件，**本轮没有运行这些新界面的产品测试**。

- 已配置模型的作者从正文到首个候选，只经过准备、可查看的发送确认；采用为独立动作。不得因面板重排增加新模型调用。
- 新模型保存成功后出现在选择器且已选中；保存失败不显示“可用”。旧任务保留原模型快照。
- 每一个禁用主按钮旁有当前唯一、可行动的原因；保存失败、缺模型、缺同意、运行中、选区失效、过期对象均可独立验证。
- 连击发送不会生成多个服务商请求；响应丢失后的刷新只读；重开页面不自动发送或采用。
- 从范文分析确认规则后，可直接将该确切版本加入本章规划；规划冲突不能覆盖作者已有修改。
- 改写采用前看得到原文范围及候选差异；正文版本改变后不能写入旧选区。
- 来源过期的事实/评审与正常对象有清晰区分，受影响章节可直达；筛选列表不调用模型。
- 备份完成与恢复完成分别可辨；刷新不丢失持久恢复入口；复制启动信息不会把原数据根误认成恢复根。
- 键盘可完成配置、准备、发送、采用、规则确认和恢复；读屏可获知状态；窄屏不遮挡正文、确认控件或错误。
- 模型请求次数用受控服务端记录验证，文字/UI 行为用对应组件测试和少量真实浏览器路径验证；按仓库规定跑受影响检查及交付门禁，不增加重复审查轮次。
