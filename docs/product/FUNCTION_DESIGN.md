# 下一阶段功能设定：把现有写作工具连成长篇创作流程

更新：2026-10-22。核对基线：`57ed00f`，`feature/rf15-17-backup-longform-release`。本文件是**待实施设计**，不是已实现能力清单；这里的对象名、接口和首版额度均为建议契约，需要实现时落到现有架构和测试中。当前能力及交付证据分别见 [功能矩阵](../FEATURE_REALITY_MATRIX.md) 和 [PLAN](../../PLAN.md)。

本轮只设计功能、流程和 UI，并交接到 GitHub。高开发量或高模型调用量的功能交由后续 AI 实现；本文不发起任何真实模型调用，不给“可以自动写完长篇”作提前承诺。

## 1. 判断：现在最缺的是什么

现有项目已经能管理小说和章节、自动保存正文、保留历史、导出 TXT；也能配置模型、粘贴范文做对照分析、确认写作规则、保存章节场景规划、生成候选并由作者采用。它还具有带原文版本的事实、有限的前文召回、一致性评审和修改影响追踪。当前分支另有备份、独立恢复和十万字合成样本工程评测。

主要缺口在三个地方：**不知道从全书计划走到今天这一章；不知道 AI 本次为什么选这些资料、花了多少；写完一章后仍需要作者自己串起下一章和未处理问题。** 应先补这条工作路径，再扩大模型调用规模。

| --- | --- | --- | --- | --- | --- |

## 2. 共用产品约束

- 继续复用小说、人物、设定、卷章、正文修订、规则版本、事实版本和任务；新增界面不再造第二份人物或事实数据库。
- “计划如此”“模型建议如此”“正文已经发生”分别显示。只有作者确认且来源有效的正式事实进入默认事实召回；计划与候选可以作为另有标识的写作指导。
- 预览、切换页面、刷新、导入识别和查看报表不调用模型。发送动作显示模型、发送范围、调用上限和费用状态；所有收费动作能追到一次明确的用户动作。
- 保留已有冻结上下文、并发版本检查、幂等采纳及来源变化追踪。页面变简洁不意味着把这些约束删掉。
- 当前 60,000 字符总上下文、24 条/约 10,000 字符记忆预算、逐段 200–300 字和单轮 10 次/3,000 字保持有效。新能力若需要不同契约，新增明确的任务类型并单独验证，不能悄悄放宽旧接口。
- 原文始终由作者采用才进入正式正文；AI 不自动确认事实、发布规则或改变伏笔状态。失败不会静默重试；中断后先恢复状态，不重发网络请求。
- 所有持久写入使用当前版本条件；跨小说引用、已删除来源、未知字段和超额输入在服务端拒绝。所有新增业务数据进入备份/恢复覆盖范围。
- 下文接口仅是实现定位草案。采用现有 `/api/v1`、Session、CSRF、错误格式和归属校验；不要为方便新页面新增通用文件路径读写或任意 URL 代理。

## 3. F01：小说工作台与继续写作

**作者要完成的事：** 打开软件后直接回到要写的章，先看到会妨碍写作的事项，再看到本次写作目标。

**分两层实现：** A1 只调整入口、布局和现有接口已能提供的状态；缺少接口的全书统计或统一待办不展示假数字，原型示例不能带进生产。下面的汇总读模型、全书统计和作者定稿状态属于 A2 扩展，补齐接口与持久化后再开放，不阻塞 A1 的可用界面。

**流程**

1. 小说列表每张卡显示书名、已保存字数、最近编辑章、最近活动时间；主要动作是“继续写作”。
2. 小说内工作台显示当前卷、下一章节卡和本章 1–3 个重点。主要动作仍是进入正文，设定和人物作为辅助入口。
3. “待处理”按正文冲突、未采用候选、来源失效事实、未完成评审分组；每项有数量、发生位置和直达操作。来源过期只影响相关 AI 动作，不阻断手动写作。
4. 作者可把章节标为“草稿 / 待检查 / 定稿”。系统可提示“还有 2 项待处理”，不能因为生成完成就自动标记定稿。

**对象 / 接口建议**

- `ProjectWorkspace` 是派生读模型：`last_opened_chapter_id`、按已保存正文计算的字数、章节状态汇总、有限分页的行动项；不复制正文。
- `ChapterEditorialState` 保存作者选择和版本，独立于正文修订；`last_opened_chapter_id` 是本机偏好，删除章节后安全回退。
- `GET /projects/{id}/workspace` 返回汇总和来源更新时间；`PUT /chapters/{id}/editorial-state` 只写作者状态。不要让主页为每章下载整份正文来统计字数。

**失败与边界：** 部分汇总读取失败时显示具体区域错误和重试，已有“继续写作”仍可用；旧链接章节被删除时回到卷章列表。工作台不是新的任务引擎。

**验收：** 最近编辑章一键进入；候选仍不计正文总字数；章节改名/排序/删除后入口有效；同一问题不重复计数；无模型配置也能进入写作；刷新不会触发生成或修改定稿状态。

**F01-B 候选处理衔接（交付包 B）：** 工作台的“待采用”直接打开原文/候选对照，避免作者反复查找任务。只读差异比较在本地完成，零模型调用，模型原始候选保持不可变。若提供“编辑后采用”，编辑结果应保存为有作者来源标记的派生草稿，保留 `source_candidate_id`、正文基线修订和改写原选区；不能修改原模型结果或伪造新模型调用。采用前仍做版本与原选区校验，并在事务中提交幂等回执，失败保留编辑草稿；正文被其他窗口改动时先比较新版本，不自动合并覆盖。该能力需要独立持久化契约，不能直接把页面 `contenteditable` 内容当成已保存候选。具体状态与交互见 [操作流程](WORKFLOW_DESIGN.md)。

该子项验收：作者修改但尚未确认时正文不变；刷新/重启后派生草稿可恢复且来源明确；重复采用不重复追加；正文或原选区改变时拒绝旧版本采用；模型原始候选与失败证据仍可查看。

## 4. F02：全书—分卷—章节规划

**作者要完成的事：** 把“这本书要写什么”拆到“这一章必须发生什么变化”，并知道哪些目标还没落实。

**流程**

1. 全书卡填写核心矛盾、主人公欲望、主要阻碍、预期变化与大致篇幅。允许暂不确定结局，未知信息保留为空。
2. 分卷卡引用全书目标，填写开局状态、核心冲突、转折、卷末变化；每个目标可挂到已有章节，不强迫重建卷章。
3. 章节卡沿用现有重点、冲突、场景和节拍，增加它服务的卷级目标；作者手工拖动计划顺序时显示受影响的引用。
4. 可选“建议拆分”先预览选定目标和既有规划，再明确调用一次模型，生成建议卡。作者选择采用哪些卡，才创建/修改真实规划。
5. 写完后由作者标记某个目标“已体现 / 延后 / 放弃”，可关联已保存正文位置；计划进度和正文字数分开展示。

**对象 / 接口建议**

- `ArcPlanRevision`：`scope_type`（全书/卷）、已有 `scope_id`、目标/阻碍/转折/结果、`parent_goal_ids`、版本。既有文本大纲仍是已有来源，通过引用关联，不能双向无条件覆盖。
- `GoalLink`：目标 ID、章节 ID、状态、可选正文修订与引文；章节计划继续使用现有 `ChapterPlan`，只增加可选目标引用。
- `GET/PUT /projects/{id}/arc-plans`；计划建议复用冻结发送与候选确认机制，新增 `plan_proposal` 类型，不能直接运行批量章节写入。

**失败与边界：** 成环的父子目标拒绝；删除/移位章节后链接显示失效而非悄悄换章；生成建议期间手工改动规划，采用时冲突并保留建议。首版不自动推断情节是否精彩或商业可行。

**验收：** 同一目标可分布多章；未填结局也能保存；建议未采用时卷章零变更；重复采用不重复建章；修改卷计划不改已冻结任务；计划有变而正文不变时不伪造正文修订。

## 5. F03：伏笔、事件与人物状态时间线

**作者要完成的事：** 记住哪些承诺尚未兑现、人物在某个时间点知道什么、拥有何种状态，以及改前文会牵动哪里。

**流程**

1. 从规划或正文选段创建“伏笔卡”：内容、涉及人物、预计埋设章、预计兑现章/卷、优先级。状态为“计划 / 已埋设 / 推进中 / 已兑现 / 已放弃”。
2. “已埋设”和“已兑现”由作者标记，并绑定相应正文修订与原句；无法找到证据时可以保持计划，不能显示已兑现。
3. 事件表同时显示叙述顺序和故事时间。支持“在事件 A 之后、事件 B 之前”这类相对关系，不要求每部小说填公历日期。
4. 人物状态卡按事件区间记录身份、伤势、持有物、知情范围等；链接已有角色及已确认事实。前后状态并存，不能用“最新伤势”覆盖早期历史。
5. 到预计兑现位置时出现待办。它是计划到期提示，不是 AI 判断作者写错；作者可以延期、改计划或放弃并记录理由。

**对象 / 接口建议**

- `PlotThreadRevision` 保存伏笔计划和作者状态，`EvidenceAnchor` 引用章节、正文修订、原句和发生位置。
- `StoryEventRevision` 保存故事时间标签和相对事件关系；`EntityStateInterval` 引用已有角色/事实版本及起止事件。事实正文仍由现有记忆模块维护。
- `GET /projects/{id}/timeline` 支持按角色/卷/状态筛选；伏笔、事件、状态区间分别用有版本条件的命令写入，避免一个巨大表单覆盖所有资料。

**失败与边界：** 不把章节顺序当成事件发生顺序；倒叙合法，时间关系成环需要修正；同一人物互斥状态重叠只提示作者核对，不能自动删除一条。原文改变后证据失效，已兑现卡显示“证据待复核”。批量 AI 提取后置，所有结果先成为建议。

**验收：** 倒叙样例可正确展示；同名角色不混用；故事时间未知可保存；已兑现事件源文改变后出现待办；未来计划不冒充前文已发生事实；跨小说事件引用拒绝。

## 6. F04：可控制的记忆召回

**作者要完成的事：** 在发送前快速看到 AI 要用什么，并能补上遗漏的关键事实，不必把整本小说塞进去。

**流程**

1. 写作侧栏“本次依据”显示已选事实、来源章、选入原因、占用字符和省略数量，默认先展示摘要。
2. 点击“调整依据”可按人物、章节、关键词和有效状态检索；首版使用本地索引/现有确定性算法，操作不调用模型。
3. 作者把关键事实固定到本次任务，或排除与当前场景无关的事实；可另存为本章偏好，但每次准备任务都重新校验来源。
4. 预算条区分正文、规划、规则和事实；固定项超出预算时明确列出超额项，请作者调整。不能悄悄丢掉固定项，也不能绕过总上限。
5. 点击“重新准备”生成新的冻结上下文，展示与上次选择的差异。旧任务不随筛选变化而改变。

**对象 / 接口建议**

- `RecallPolicyRevision`：章节归属、固定/排除事实 ID、可选角色/章节筛选；固定 ID 在准备时解析为具体有效版本。
- `RecallSelection`：选中版本、来源修订、原因（作者固定/关联/时间顺序）、省略原因与字符用量，写入既有 ContextPack 来源清单。
- `GET /projects/{id}/facts/search` 分页返回可用事实；`POST /chapters/{id}/recall-preview` 是不发模型的预览；既有准备任务接口接收经校验的策略版本。

**失败与边界：** 前文章节范围、确认状态、来源有效性和项目隔离依然强制；失效固定项必须提示重新确认。首版不做向量服务、自动摘要或外部索引，避免为“搜索更聪明”先引入调用成本和第二份事实源。

**验收：** 固定项优先且可追溯；排除项不进入新任务；超过 24 条/事实字符上限时无静默截断固定项；同一输入结果稳定；改前文后固定项被正确判过期；只打开或筛选界面时受控模型服务请求计数为 0。

## 7. F05：长篇任务编排与章节候选稿

**作者要完成的事：** 按已确认的场景计划推进一章，知道写到哪里；失败后能接着处理，而不是从头重新发起。

这是高开发量、高调用量项目，**本轮仅设计**。先做“任务列表与进度”即可受益；整章候选生成要在 F04/F06 完成后单独实现，不通过增大现有续写按钮上限完成。

**首版流程**

1. 作者选择一章及计划版本、模型、目标场景、最多步骤和总输出额度。系统列出将进行的子任务和所有可能发送的来源。
2. 任务列表只记录计划；点击具体子任务后复用现有逐段发送、候选和采纳。采纳后更新场景进度，下一步提供明确入口。
3. 可准备后续章节任务，但不自动发模型。每章开始前读取当前已保存正文和最新有效事实，重新冻结上下文，不能沿用上一章的旧事实快照。
4. 失败显示任务、已完成段落、错误与剩余额度；作者选择重试失败段、换模型重新准备或结束。重试产生新的 attempt 并计费，不能伪装同一次免费恢复。

**后续扩展：章节候选稿**

- 新增独立 `chapter_draft` 类型，在作者明确同意的单章范围与额度内生成多段候选；前一段未采用文本仅作为“本次候选稿”传给下一段，不能成为正式事实或进入别的任务召回。
- 新类型必须单独定义字数与段数契约、预算和停止点。建议首个版本仍只做单章、最多 10 个子请求，排队下一章前停在“等待作者”。不得顺带把既有 200–300 字候选校验放宽。
- 作者查看整章候选稿与当前正文的差异，可分段或整章采用；采用时检查基线版本，事务写入与幂等回执保持一致。正文有手改时保留候选供比较，不自动覆盖。
- 暂不做无人值守整本生成、自动事实确认、多模型互相循环审稿和失败自动补发。它们使成本与质量归因失控，也没有当前作者验收证据支持。

**对象 / 接口建议**

- `WritingJob` 引用小说、章节计划版本、源修订、模型快照、步骤预算和价格版本；`JobStep` 引用实际 run/attempt；`DraftAssembly` 仅引用候选及顺序，不复制为正式正文。
- 状态：`planned → ready → running → waiting_author → completed`；旁路 `paused / interrupted / failed / cancelled`。`completed` 指任务完成，不能等同章节定稿。
- `POST /projects/{id}/writing-jobs` 只创建计划；`POST /writing-jobs/{id}/prepare-step` 冻结当前子任务；send/adopt 复用或扩展明确类型的既有契约，禁止启动后自动扫库找下一章。

**失败与验收：** 进程退出后不自动重发；双击不重复请求；终止后保留已生成候选且不再调度；切换模型使未发送步骤重新预览；预算耗尽停在准确步骤；源章改动后停止使用旧依赖；所有候选未采用前 TXT 导出和正式事实保持不变。用受控服务证明调度次数，再由作者评价真实模型的章节质量，二者分开报告。

## 8. F06：用量账本与费用预算

**作者要完成的事：** 知道本章、这本书和某类操作用了多少；发送前能选择值得花费的操作。

现有 `GeneratedText` 只返回文本和模型名称。工程评测中的 token 估算不能代替生产用量；实现需要补齐供应商响应解析、持久记录和请求生命周期。

**流程**

1. 模型设置可填写按百万 token 的输入、输出及可选缓存价格、币种、生效时间；默认“价格未填写”，不预填看似实时的价格。
2. 发送前显示上下文字符数、token 估算及方法、输出上限和预计费用范围。供应商不提供可靠 tokenizer/计费规则时明确写估算，不把字符数当 token。
3. 每次请求记录服务商返回的输入/输出用量、调用类型（生成/分析/评审）、成功或失败、耗时；费用按当时价格版本计算，未知部分留空。
4. 作者可设单任务、小说本月的预算。普通模式提示预算；严格模式在可计算的保守预留超额时拒绝发送。价格或计量规则不完整时不能启用货币严格模式，仍保留现有次数/输出额度保护。
5. 小说报表按模型、章节与操作汇总“估算 / 服务商报告 / 未确认”；只对同币种相加，不自动换汇。作者可以导出无正文、无密钥的账单 CSV。

**对象 / 接口建议**

- `UsageAttempt`：唯一 attempt ID、逻辑任务与操作、模型快照、输入字符数、估算版本、报告 token、状态、起止时间、计量来源；不存原始请求/响应头或 Key。
- `PriceRevision` 使用十进制定点金额；`BudgetReservation` 在取得发送权前事务预留，防止两个窗口同时透支。返回后结算；超时等未知结果保留“金额待确认”，不能按 0 元释放继续批量调用。
- `GET /projects/{id}/usage`；`GET/PUT /model-profiles/{id}/prices`；`GET/PUT /projects/{id}/budgets`。在统一 provider 调用入口记录，但由各业务调用传递明确归属，不能漏记范文分析或评审。

**失败与边界：** 供应商可能在失败/超时后收费；本地软件不能保证控制服务商最终账单。严格模式是发送前的本地支出控制，只有已支持计费规则才可使用；未知费用必须单列。调用次数、估算量、报告量和金额不能相互冒充。

**验收：** 成功/鉴权失败/超时/响应无 usage 各自正确记账；重复回调不重复结算；历史价格修改不改旧账；同币种分别汇总、未知不等于零；并发发送无法越过本地预留；查看账单和修改价格不调用模型。不要用提高输出 token 上限掩盖范文分析失败。

## 9. F07：旧稿导入与外部 AI 交接

分成两个独立交付，先实现零模型调用的旧稿导入。备份恢复继续解决“恢复整个数据根”，不能把它改造成章节导入器。

### F07-A：旧稿导入

1. 作者选择本地 TXT/Markdown 或粘贴文本，系统本地解析并显示编码、章标题、字数、未归类段落；首版仅 UTF-8（允许 BOM），其他编码提示先转换，不猜测后静默损坏原稿。
2. 选择受控标题格式或手工调整章节分界。标题重名允许但明确显示；前言/卷标题/末尾残段都必须有归属，不丢弃未识别文本。首版不开放任意正则执行。
3. 预览将创建的新小说、卷、章及顺序，选择“确认导入为新小说”。整次提交有幂等键并在事务中完成；首版不导入覆盖已有小说。
4. 完成后打开第一章。提取记忆是独立可选动作，先选择章节与预算；导入本身不向云端发送正文。

建议首版单文件上限 10 MiB、500 章，并同时校验既有单章正文上限；这是待实现时验证的有界契约，不是已支持能力。超额显示精确位置，不静默截断。Markdown 仅作为文本导入，不获取远程图片或执行 HTML。

对象建议：`ImportPreview` 保存源哈希、解析器版本、分章结果与到期时间；`ImportReceipt` 绑定幂等键和新小说 ID。接口建议：`POST /imports/preview` 与 `POST /imports/{id}/commit`。上传由浏览器显式选择文件，不让请求提供任意服务端文件路径。

验收：含 BOM、空章、重名、序言、尾段和超长章样本；去除明确标题包装后的正文逐字可核对；取消不建小说；重复确认只建一份；中途失败不留半本；跨进程重试能读取回执；导入全过程模型请求为 0。

### F07-B：选择性外部 AI 交接

1. 作者选择一章任务、规划、已确认规则和必要事实，预览待导出内容、字数和省略项；默认不包含整本正文、范文原句、其他小说资料、模型配置或 Key。
2. 导出 `task.md`、结构化 `context.json` 与 `manifest.json`。清单包含格式版本、目标小说/章、来源修订、上下文哈希、返回格式和限制；包只是文件，不自动上传或发送给外部服务。
3. 其他 AI 返回正文候选/建议 JSON 或可粘贴文本。导入时作为“外部候选”显示，来源标为作者导入，不能假装经过本软件模型调用。
4. 作者检查差异后明确采用；正文或规划基线变化时提示冲突。外部建议事实仍要核对本地原文引文并确认，不能凭外部声明直接成为正式记忆。

对象建议：本地持久 `HandoffSnapshot` + 导出用 `HandoffManifest` + `ExternalCandidate`，复用归属、基线和幂等采纳；接口建议 `POST /chapters/{id}/handoffs/preview`、显式下载端点和外部候选导入端点。文件清单是可编辑文本而非数字签名；哈希用于判断一致性，不能证明来源可信。

**待实现的返回校验契约：** 导出前在本地保存不可变 `HandoffSnapshot`，记录服务端生成的 `handoff_id`、小说/章节归属、正文与规划基线、实际选取的来源版本、上下文哈希、候选类型、返回格式版本和长度上限。导入 JSON 必须绑定已有本地交接任务，并核对 `handoff_id`、格式版本与上下文哈希；归属、基线和允许操作以本地快照为准，不能相信外部 manifest 或返回文本自报的身份、版本与权限。未知交接 ID、错小说或哈希不符拒绝导入；本地来源已改变时保留冲突提示，不能按外部声明改回旧版本。粘贴纯文本时由作者先选择已有交接任务，服务端执行同样的归属和基线核对，不从正文猜测任务。

建议首版返回文件/请求体上限 256 KiB，并在 JSON 解析前校验字节数；正文另按本地快照声明的字符上限、目标候选类型和当前采用接口约束校验，不把文件大小上限当作正文许可。沿用逐段候选时仍执行既有 200–300 字限制，其他候选类型须另行定义并验证有界契约；未知字段、重复字段、非法编码、超长文本和超额建议项均拒绝，不静默截断。以上是待实施时验证的建议边界，当前产品尚不支持此导入能力。外部事实建议仍须定位本地原文引文并经过作者确认，交接身份校验不能替代事实证据核对。

验收：包内无 Key/内部日志/未选正文；拿错小说的返回被拒绝；畸形 JSON、未知字段、超长内容安全拒绝；同一返回反复导入不产生重复采用；外部文本中的“忽略规则”等内容只作为文本，不能触发命令或改变权限；交接包不能替代灾备文件。

## 10. F08：写作方法验证与复用

> 2026-11-18 实施状态：main 已接入方法标注、A/B 试写、作者评分与个人模板，见 [操作与契约](../METHOD_VALIDATION.md)。[PR #49](https://github.com/King70404/AI-Writer-project/pull/49) 已合并为 `16adc1e`；完整 Windows 门禁已通过，见 [F08 验证](../F08_WINDOWS_GATE_20261117.md) 与 [PLAN](../../PLAN.md)；下文保留原设计与验收要求。

**作者要完成的事：** 从范文提炼一个可解释的方法，再判断它是否真的改善自己的章节，而不是积累越来越长的规则。

**流程**

1. 在已有确认规则上增加场景标签（对话/追逐/铺垫等）、适用条件、不适用条件和规则优先级；默认选少量与当前场景相关的规则。
2. 作者可手工把一段自己的正文标为“体现该方法 / 没体现 / 不适用”，绑定规则版本和正文修订，写一句判断依据。
3. 可选对照试写：对同一已冻结场景，分别“不选这条规则”和“选这条规则”生成两个独立候选。首版最多 2 次显式生成，评估默认由作者完成；额外 AI 评审另预览、另计费，不做循环优化。
4. 候选以随机 A/B 顺序展示，作者比较焦点清晰度、行动连续性、对话潜台词、场景停留、原创表达，再揭示使用的方法。评分只能表达本次作者偏好，不能成为模型保证。
5. 已验证方法可保存为个人模板，跨书使用时“复制为本书新规则版本”并记录来源；默认不复制范文原文、角色名和其他小说情节，也不建立跨小说自动同步依赖。

**对象 / 接口建议**

- 延伸已有 `WritingRuleVersion` 的可选元数据；`MethodTrial` 引用规则版本、规划/正文基线、两份候选、作者评分与说明。
- `RuleTemplate` 只存方法、适用条件和来源标识。导入某小说时走作者确认并创建本书版本，不能直接把全局模板当成已确认的本书规则。
- 试写准备/发送/候选仍走现有 provider 与 F06 账本；新增 trial 类型用于关联，避免再造一个不受预算管控的模型调用入口。

**失败与边界：** 两候选中一份失败就显示不完整，不偷偷补发；修改规则不重写旧评分；多规则相互冲突提示作者选择，不自动追加“最终规则”。分析的写作原因依然是推测；局部相似度检查不等同版权判定或原创性保证。

**验收：** A/B 来源版本完全相同、只有声明的规则变量不同；不选择试写时零新增调用；评分不自动采用候选；规则更新保留历史评估；跨书模板无正文泄漏；删除一个模板不使已复制的规则失效。全书文学质量仍由真实写作样本和作者评估证明。

## 11. 交给下一位 AI 的执行顺序

| 交付包 | 包含范围 | 可独立完成的结果 | 依赖与停止点 |
| --- | --- | --- | --- |
| A：作者工作台 | F01 的继续写作与已有状态入口；配套 UI 布局、导航和状态区 | 从首页进入上次章节，正文、资料与 AI 操作位置清晰 | A1 复用现有 API，无接口的汇总/定稿状态列 A2 扩展；候选编辑、账本、增强召回不放进第一包 |
| B：候选处理与用量控制 | F01 候选对照/作者编辑衔接；F06 用量记录、估算标识和预算 | 能比较并采用候选，能查明一次调用的用量并控制后续支出 | 编辑候选先补持久化；预算在计量契约完整后启用，不把未知当 0 |
| C：长篇故事控制 | F02 分层规划；F03 伏笔/事件/状态；F04 可调召回 | 从全书目标找到本章任务，追踪情节，并控制发送依据 | 包内先规划/伏笔，再增强召回；AI 批量提取和语义服务后置 |
| D：跨章与资料交接 | F07-A 旧稿导入、F07-B 外部交接；F05 有界任务编排与后续章节候选稿 | 旧稿能进入项目，选定任务可移交，生成失败后可接续 | 导入/交接可独立先做；批量生成依赖 B 的预算与 C 的召回，单章验证后再考虑跨章自动调度 |
| E：写作方法验证 | F08 方法适用性与对照试写 | 知道哪些方法改善自己的段落，可复用少量有效规则 | B 的账本及候选隔离先就绪；不把自评或假模型输出当文学质量验收 |

每个交付包应有一个主 Issue，写清范围、实际改动、必要检查和精确代码版本。不要把每个表单字段拆成一次用户“继续”。实施 AI 先检查当前 GitHub/分支状态和本文件适用性；若契约已经变化，更新设计与验收，再修改代码。不要用此设计取代当前运行安全、备份、数据隔离和冻结验收约束。

**所有包共用的完成证据：** 真实前后端接线；空态/加载/失败/冲突/重启恢复；明确的作者确认与收费时点；受影响测试及约定的交付门禁；自有隔离数据上的浏览器流程；当前文档与 GitHub 同步。新调用要有受控服务次数断言。真实模型文学质量和实际费用另外记录，不使用工程样本结果代替。
