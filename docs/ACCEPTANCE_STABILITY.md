# 交付验证与稳定性

2026-09-27 用户明确要求以最终可用成果为最高标准，去掉重复审查和中间停点。本协议代替旧的多轮 RC、连续两次全门、另建 formal/recovery Issue 流程；历史 PASS/FAIL 不改写。

## 一次完整交付

1. 开发时运行受影响的测试，遇到真实失败就修复。同一已授权交付任务持续推进，不因内部 RF 编号或一次开发失败要求用户再说“继续”。
2. 实现接通后，对精确候选运行一次 `scripts/quality_gate.ps1 -IncludeE2E`。它已经包含 Default，不另外重复运行 Default 和两次 Full。Windows hosted Full 可作为独立执行证据，不复制本地日志冒充云端检查。
3. 完成任务要求的隔离启动和作者流程，核对真实持久化、浏览器诊断及 Git/数据边界。自动化 E2E 已覆盖的操作不机械重复；新增交互或尚未覆盖的风险做针对性实际浏览器验证。
4. 活动 Issue/PR 独立记录候选 SHA、检查结果、剩余限制和最终 PASS/FAIL。最终通过后依授权合并；PR #9 未最终 PASS 不合并。无需另开 formal Issue。

只在新增变更、失败或未解风险要求时扩大/重复检查。文档状态调整不清零已验证且未变的代码证据。新代码必须验证，旧失败不得被删除或改写为通过。

## 仍必须验证的行为

- 真实根 `启动 AI 网文助手.cmd` 的测试只使用子进程专属 `LOCALAPPDATA` 隔离目录。记录自动打开入口；支持的受控浏览器明确绑定该服务 URL 验证渲染和操作。窗口标题、进程退出码、HTTP 200 都不能单独替代完整作者流程。
- 不读取、枚举或修改正式 `%LOCALAPPDATA%\AIWebNovel` 数据及备份；只清理任务自己创建且已校验边界的路径。
- 不删除/弱化/跳过既有测试，不降 coverage，不用 timeout inflation、规避性 sleep/retry 或静音 warning 造绿。
- 前端与浏览器无未解释的 React warning、console.error、pageerror、requestfailed。预期错误必须按具体测试契约 allowlist。
- 删除小说后，子内容历史列表、旧 cursor 页、旧/当前修订正文 API 都拒绝普通读取；原修订逐条保留，允许追加删除标记。
- 作者页面隐藏内部 ID/并发信息；作者明确确认前 AI 不能写正式正文/事实。重复采纳、旧候选、正文冲突必须安全拒绝或幂等处理。
- 已知时序问题修复后可用既有 20 targeted + 5 file 稳定性入口；已修复且代码未变不反复重跑。新失败优先查异步语义、状态污染和资源争用，不增加超时掩盖。
- M0–M7 tags 和 24 份冻结文件不改写。新 AI 迁移属于当前明确授权范围，须验证升级/旧数据保留，不误判为未经授权漂移。

## CI 与同步

Windows CI 使用锁定依赖、临时数据和最新 PR head，保留失败产物。main required checks 与 up-to-date 规则由 owner/套餐能力决定，管理限制如实记录，不伪称配置完成。GitHub 是共享事实源；PLAN 只写当前摘要，细节放活动交付 Issue。
