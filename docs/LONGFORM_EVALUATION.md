# 十万字长篇规模评测（RF-16）

本页是 [#32](https://github.com/King70404/AI-Writer-project/issues/32) RF-16 的评测契约。**样本、指标和通过阈值在首次测量前写定并单独提交**；测量结果写在文末“实测结果”，不回头修改阈值。若阈值未达到，如实记录 FAIL 与原因，修复后以新运行重新记录，不放宽标准。当前交付状态以 [PLAN.md](../PLAN.md) 为准。

路线约定：10 万字是本阶段验证节点，百万字是长期目标。本评测证明的是**软件在 10 万字自有合成样本上的持久化、召回、变更影响、备份恢复、性能和调用计量行为**；测试通过不等于小说文学质量已被证明，也不代表真实付费模型的输出质量与实际费用。

## 1. 样本（预先登记）

样本由确定性生成器 `scripts/longform_eval.py` 生成，不含随机数、作者正式内容或第三方文本；同一参数两次生成的文本逐字节一致（生成器自带 SHA-256 指纹）。全部内容是为评测编写的合成中文段落，不具文学价值。

| 项 | 规模（完整运行 `--scale full`） |
| --- | --- |
| 主评测小说 | 1 部：小说简介、大纲、设定（Story Bible）、12 个人物 |
| 卷章 | 3 卷 × 16 章 = 48 章，章内位置间隔 10，便于调整顺序 |
| 正文 | 每章约 2,300 个非空白汉字；全书 ≥ 100,000 个非空白字符（含 AI 采用段落前已满足） |
| 作者修订 | 每章先保存草稿、再保存定稿，至少 2 个正文版本 |
| 事实 | 每章 3 条由作者确认的事实（引文逐字取自该章定稿），另每 4 章 1 条保持待确认、每 6 章 1 条确认前驳回 |
| AI 续写任务 | 4 章各 1 个任务：生成 2 段（受控模型），作者采用第 1 段、丢弃第 2 段，随后按新正文重新核对并确认本章事实 |
| 一致性评审 | 4 章各 1 次：准备、确认发送（受控模型返回引用实际事实与原句的结果） |
| 准备态任务 | 测量阶段对 48 章各准备 1 个续写任务（只组装冻结上下文，不调用模型） |
| 召回探针 | ≥ 12 对：后文章节结尾显式再次提及某条前文确认事实的专有名词 |
| 隔离对照 | 第 2 部小说（1 卷 3 章，含已确认事实，用词与主样本重叠），验证跨小说隔离 |

`--scale small` 使用同一生成器缩小章数和字数，供快速自动测试使用；结论只来自完整运行。

## 2. 执行方式

- 只在 `--work-root` 指定的自有空目录中创建隔离数据根与报告；目录必须是绝对路径、不在仓库内，运行结束后删除自己创建的数据根（`--keep-data` 时保留）。不读取、枚举或修改作者正式数据根、正式备份或真实 Key，清除 `AIWEBNOVEL_DATABASE_URL`。
- 数据库用 Alembic 迁移到当前最新版本；全部写入经真实 FastAPI 应用（Session/CSRF/If-Match 等边界不变）的 HTTP 接口完成，进程内 `TestClient` 调用，计时包含应用栈处理。
- 模型是本机 loopback 上的确定性 OpenAI-compatible 假服务（`/chat/completions`）：续写返回 250 字合成段落；评审返回引用实际原句与所给事实编号的 JSON。服务记录每个请求的字符数，按下述估算规则给出 token 估计。**不调用任何付费 API。**
- 运行时 AI 不自动确认任何事实、规则或正文：样本中每次确认、采用、丢弃都是评测脚本显式发出的作者操作，并计数核对。
- 输出：`<work-root>/longform-report.json` 与 `longform-report.md`。仓库只提交本页汇总，不提交原始数据、数据库或运行日志。

## 3. 指标与通过阈值（预先登记）

延迟为单进程、进程内 HTTP 调用的墙钟时间；p95 按最近秩法计算。

| 编号 | 指标 | 通过阈值 |
| --- | --- | --- |
| LE-01 | 样本规模 | 主小说 ≥ 40 章、≥ 100,000 个非空白字符；每章 ≥ 2 个作者正文版本；确认事实 ≥ 3 条/章；存在待确认、驳回事实与对照小说 |
| LE-02 | 重启后持久化完整性 | 重新创建应用后：全部章节正文 SHA-256 与预期一致、每章正文版本数、各状态事实数与版本、任务/候选/评审数量与状态全部一致；**0 处不符** |
| LE-03 | 写入延迟 | 章节正文保存 p95 ≤ 1,000 ms 且最大 ≤ 3,000 ms；事实创建/确认 p95 ≤ 1,000 ms |
| LE-04 | 读取延迟（完整样本建成后） | 章节正文读取 p95 ≤ 300 ms；全部 48 章长篇记忆工作台读取 p95 ≤ 2,000 ms |
| LE-05 | 召回正确性与预算 | 每章：召回 ≤ 24 项且按产品计法 ≤ 10,000 字符；每项均为同一小说、当前顺序在前、作者已确认、来源修订有效的当前事实版本；待确认/驳回/失效/对照小说事实出现 0 次；召回数 + 省略数 = 独立计算的合格事实数。**0 处违例** |
| LE-06 | 定向召回探针 | 命中率（探针事实出现在后文召回中）≥ 90% |
| LE-07 | 变更影响 | 三个场景（修改前文正文、修订已确认事实、调整章节顺序）后：工作台影响章节集合与由已记录依赖（事实来源、评审冻结事实、任务冻结记忆来源、章节先后）独立推算的集合**完全相等**（查全 100%、查准 100%）；变更后召回复查 0 违例；既有任务冻结上下文哈希不变 |
| LE-08 | 备份/校验/恢复 | 对完整样本创建备份并校验为 `valid`；恢复到新数据根后，全部业务表逐行与源库一致，恢复副本经 HTTP 读回全部章节 SHA-256 一致；创建、校验、恢复各 ≤ 60 s |
| LE-09 | 存储占用 | 数据库文件 ≤ 200 MB；备份 ZIP ≤ 200 MB（记录实测值） |
| LE-10 | 生成上下文组装 | 48 章准备续写任务 p95 ≤ 3,000 ms；冻结上下文字符数 ≤ 60,000；发往模型的单次请求消息 ≤ 100,000 字符 |
| LE-11 | 模型调用计量 | 假服务收到的请求数 = 显式“生成”与“确认发送评审”操作数（完全相等）；准备任务、工作台、刷新、备份恢复期间 0 请求；每任务请求 ≤ 其步数上限，每评审 ≤ 3 次；记录请求数、发送/返回字符数、估算 token（按操作类型汇总） |
| LE-12 | 作者权限 | 评审建议的候选事实不自动保存（发送前后事实数不变）；采用数 = 显式采用操作数；已确认事实数 = 显式确认操作数 |
| LE-13 | 整体资源 | 完整运行（构建 + 测量 + 变更 + 备份恢复）墙钟 ≤ 30 分钟；进程峰值常驻内存 ≤ 1.5 GiB |

token 估算规则（仅用于量级记录，不是真实分词器）：每个 CJK 统一表意字符计 1，其余非空白字符每 4 个计 1（向上取整）。**不计算货币费用**：真实单价、真实分词与服务商计费方式均未验证。若要换算，费用 ≈ 输入 token × 输入单价 + 输出 token × 输出单价，单价由作者按所选服务商当期价格填写。

## 4. 明确不在本评测中验证

- 真实 DeepSeek 或其他付费模型的输出质量、长度遵守情况、真实 token 数与实际费用；本仓库不持久化服务商返回的 usage/计费字段，本评测的计量来自受控假服务侧观察。
- 作者对情节、文笔、人物一致性的文学评价；合成样本文字不代表小说质量。
- 百万字规模及其一致性：每部小说 2,000 条事实、每章 100 份评审的上限未被突破，召回仍是确定性文字二元组关联加顺序，不是语义检索，不承诺全书事实覆盖。
- Windows 上的性能（NTFS、杀毒扫描）、DPAPI 云端 Key、浏览器界面在十万字下的渲染与交互性能、多会话并发；这些需要 Windows 门禁或后续评测。
- 未被记录为依赖的情节联系的变更影响（产品只追踪已记录的事实、评审和任务依赖）。

## 5. 运行入口

```powershell
.\scripts\longform_eval.ps1 -WorkRoot <自有空目录的绝对路径> [-Scale full|small] [-KeepData]
```

Linux 开发环境可直接运行：`.venv/bin/python scripts/longform_eval.py --work-root <绝对路径> --scale full`。退出码 0 表示全部阈值通过，1 表示存在 FAIL，2 表示参数或隔离根无效。
