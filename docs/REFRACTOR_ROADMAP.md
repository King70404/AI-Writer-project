## 执行方式

- 一次推进一个完整交付阶段。该阶段获准实施后，自主完成其中的设计、代码、测试、失败修复、文档和交付验证，不把每个 RF 清单项变成新的确认停点。
- RF 编号保留作内部依赖与证据索引；同阶段内按表中顺序推进，可以分提交、分模块开发，不能跳过前置能力或将全部五阶段一次实施。
- 每个阶段以其完成定义收尾。开发检查失败应在授权范围内修复；需要正式冻结验收时，另行记录精确候选，遵守 [验收稳定性规则](ACCEPTANCE_STABILITY.md) 的入口条件和失败停止规则。
- 正文采纳、正式故事事实和风格规则仍由作者确认。阶段粒度调整不放宽正式数据隔离、安全门、质量阈值、外部发布授权或 M0–M7 冻结历史保护。

### 已交付：范文学习与故事规划基础（RF-01–05）

把当前文本设定和卷章结构发展为可持续维护的故事规划。作者可以粘贴范文，对照句段分析作用、效果和推测意图，确认可迁移的写作方法，再将方法用于原创章节。结构化规划引用已有设定和人物事实源；独立道具/能力/地点资产库结合后续长篇记忆阶段扩展，不用重复录入阻塞当前写作流程。

完成定义：作者能在一部小说内维护上述规划，重新打开后仍可读取，并追溯适用的版本与归属；既有小说、设定、人物、正文和导出闭环不退化。各模块有明确输入输出、错误与兼容约束，并通过该阶段开发检查和交付验证。

本阶段已贯通“粘贴范文 → 对照分析 → 确认方法 → 章节规划 → 场景/推进点 → 关联资产 → 选择规则版本 → AI 上下文预览 → 生成并采纳”的作者流程，完成以下范围：

1. 定义小说/章节归属、排序、不可变版本和关联契约，复用现有小说、设定、人物与卷章。
2. 实现场景及情节推进点的维护、排序、章节关联与重新打开后的持久读取。
3. 实现章节场景对既有设定、人物资产的显式引用，保留来源版本，避免复制成两份不一致的内容。
4. 从范文分析中提炼方法，由作者编辑并确认适用范围，保存不可变规则版本。这里的 Skills 是产品规则，不是 Codex 技能安装；正文生成默认不带范文原句。
5. 把作者选定的场景、资产及规则版本接入现有 ContextPack；展示实际发送文本，已准备任务的快照不随后续规划修改而改变。

本地验证覆盖跨小说隔离、过期更新冲突、删除后子资源不可普通读取、迁移保留既有正文/历史，以及刷新和重启后的归属/版本恢复。24 个浏览器场景及清理全部通过，受控 HTTP 流程验证分析、生成和作者采纳；未使用付费 DeepSeek 验证。

验收代码 `90e396745dd107781ee2d70bcb9ce0a99373a739`；精确 Git 树、覆盖率及本地日志见 [PLAN](../PLAN.md)，外部同步结果由 #28 与 PLAN 记录。本阶段的实际操作、长度预算及长篇能力边界见 [范文分析与章节规划](REFERENCE_WRITING.md)。规划/方法复用的通过不代表小说质量或全书一致性已验证。

### 阶段 2：完成 AI 写作闭环

已完成：[PR #25](https://github.com/King70404/AI-Writer-project/pull/25) 于 2026-10-06 合并，完整 IncludeE2E 与隔离作者流程通过，最终证据见 [#24](https://github.com/King70404/AI-Writer-project/issues/24)。以下完成定义已满足，不再作为新的交接停点。

在现有本地续写/改写基础上增加云模型接入和安全 Key 管理，重建可解释的上下文，持久保存单段任务及候选，再接通幂等采纳与连续生成。复用已有小说、文本设定、人物、大纲与卷章，只补这条流程必需的接口、测试和安全契约；不先实现新的场景、故事资产或 Skills 库。

完成定义：作者能够完成“配置模型 → 准备上下文 → 生成候选 → 查看并确认采纳 → 保存”的流程；候选和任务可在重启后读取。连续生成以每次 200–300 字为受控步骤，可暂停、恢复、处理失败；重复操作、旧候选和正文冲突不能造成重复追加或覆盖。云端发送内容与费用控制在本阶段契约中明确，Key 不进入仓库、普通日志或小说正文。

RF-09 必须先于 RF-10。持续生成不等于自动把未经作者确认的内容写入正式正文，也不赋予模型正式事实提交权。

### 已交付：支持长篇记忆与评审（RF-11–14 / #30）

建立带来源和作者确认状态的故事记忆，再实现一致性评审、定向改写、跨章召回和修改影响追踪，最后将这些动作整合到作者工作台。

完成定义：用跨章样例证明已确认事实能够被召回，候选事实与正式事实可区分；修改前文后能够识别相关后文或记忆需要复核；评审建议产生可检查的修改候选，由作者决定是否采用。统一工作台能够完成这一整条流程，不依靠人工在零散页面之间补齐关键步骤。

此阶段是现有章节编辑工作区的整合与增强；当前并非没有正文编辑器，也不能把当前有限上下文拼接称为长篇记忆已完成。

本阶段已完成实现和本地完整交付验证，并通过 PR #31 合并。范围与证据统一记录于 [#30](https://github.com/King70404/AI-Writer-project/issues/30) 和 PLAN。操作与明确预算见 [长篇记忆与评审](LONGFORM_MEMORY.md)；内部 RF 连续完成，不另设交接停点。

### 下一阶段：完成长篇验证与发布（RF-15–17）

完成升级、备份与恢复，再用持续写作评估检查质量、稳定性、费用与规模限制，最后进入正式发布验收。

长篇验证先以 10 万字为节点，百万字支持作为长期目标；具体样本与资源预算在产品契约中确定，不能把目标规模写成已通过的能力。

完成定义：在自有隔离数据上验证升级和备份恢复，证明已有正文与确认事实受到保护；长篇评测按事先确定的样本、长度、质量与成本标准输出证据及限制；候选满足发布验收和交付要求。测试通过不等于已经证明小说质量，发布验收通过也不自动授权未批准的外部发布动作。
