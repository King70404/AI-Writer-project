# AI 协作：作者操作与运行契约

本页对应 [交付 #24](https://github.com/King70404/AI-Writer-project/issues/24)（RF-06–10）。交付状态和最终检查结果见 [PLAN.md](../PLAN.md)。

## 怎么使用

1. 打开小说的一章，进入“写正文”。如果 AI 助手显示需要升级，点击“备份并启用 AI 协作”，等待“AI 协作已启用，可以保存模型配置。”，然后在模型设置中添加模型。支持本地 OpenAI-compatible 服务，以及提供相同 `/chat/completions` 协议的 HTTPS 云服务。填写服务地址、模型名和单次输出 token 上限；云服务需要凭据时填写 API Key。
2. 保存正文，填写本次要求，选择“续写”或先在正文中选中文字再选择“改写选中文本”。这一步仅保存任务和上下文，不调用模型。
3. 查看准备发送的上下文、来源、截断/省略情况和改写选区。云模型还需明确确认发送。点击“确认发送并生成”才发起模型请求。
4. 阅读候选，决定追加、替换或丢弃。候选不进入 TXT 导出，也不会自行成为正文。采用后，服务器在同一事务内保存正文修订及采纳记录；重复点击或断线重试不能重复追加。
5. 续写可选择“采纳并生成下一段”。每次生成 200–300 个非空白 Unicode 字符，每段仍由作者决定是否采用。可暂停、恢复；刷新或正常重启后，任务和候选仍保留。

没有内置模型或赠送额度。这里只验证协议与数据流程，不保证任意供应商、任意模型都遵守长度要求或达到小说质量目标。

保存模型后应明确显示“模型配置已保存。密钥不会回显。”，并自动选中刚保存的模型。如果仍是“请先添加模型”，先看模型配置按钮下方及 AI 区域顶部的错误提示。浏览器页面打开不代表本机服务正在运行：关闭启动命令窗口会停止服务，需要重新双击“启动 AI 网文助手.cmd”并保持该窗口开启。连接中断时无法确认保存结果，重启后先刷新查看已有模型，避免重复添加。数据库需要升级时使用上述按钮；会话或密钥保护错误按各自提示处理。

DeepSeek 的服务地址填写 `https://api.deepseek.com`（[官方接入说明](https://api-docs.deepseek.com/)）；也兼容云端完整 `/chat/completions` 地址，不会重复拼接接口路径。模型名称填写该账户可用的实际 API 模型标识。

点击生成后，等待状态和失败原因显示在当前任务内。服务商拒绝请求时会区分密钥/权限、余额、频率、接口地址及参数问题；网络或模型输出问题也分别提示。失败后自动读取已保存任务状态，但不会再次调用模型。需要再次生成时，先按提示修正问题，再恢复任务并明确点击生成；任务已用完段数时重新准备。准备任务后修改了正文或模型配置，需要重新准备上下文，防止发送旧内容或悄悄更换模型。

## 发送与费用边界

- 任务保存模型名称、地址、模型标识及 token 上限的快照；准备后若修改配置，旧任务不能悄悄换目标发送，需重新准备。
- 小说上下文总预算为 60,000 字符，包含当前章节、大纲、设定、当前卷、同卷前一章、人物名称/定位及小说简介。每项记录实际文本、来源版本、纳入理由及省略/截断情况。人物最多稳定排序的前 100 项；这不是全书记忆或相关性检索。
- 请求还包括本次要求、改写选区（仅改写）、本任务已采用的段落，以及固定的续写/改写与数据边界指令。模型不接受项目外文件、浏览器凭据或工具执行权限。
- 一次任务最多 10 次请求、3,000 字候选总量；单段 200–300 字。单次输出 token 上限与字数独立。失败请求也消耗一次任务步数，不自动重试，不截断不合格结果冒充合格候选。
- 这些是请求次数、输出字数和单次输出 token 限制，**不是货币费用硬上限**；供应商可能按输入、输出或失败请求计费。
- 暂停阻止后续生成，不保证撤销已发送的模型请求。当前请求若完成，保留候选但不采用；程序中断后标记为“已中断”，由作者显式恢复，不自动重发可能收费的调用。

## 保存、冲突与秘密

- 任务和候选存放于所选数据根的 SQLite。正式正文继续使用不可变修订。生成和候选保存不写正文；只有作者采纳操作可以创建正文修订。
- 改写使用 UTF-16 选区坐标并核对原文，重复句子和 emoji 不会造成替换位置漂移。正文版本变化时拒绝旧候选覆盖。
- 采纳成功但后续正文读取失败时，编辑器停止写入并保留恢复入口，避免浏览器旧稿反向覆盖已保存结果。
- 删除小说后，其 AI 任务及候选不能通过普通接口读取或操作；底层不可变作者修订仍保留。
- API Key 单独用 Windows 当前用户 DPAPI 加密，绑定数据根及模型配置；不会从接口返回明文，不进入小说、Git 或浏览器持久存储。修改服务地址不得悄悄携带旧 Key，必须重新提供或清除。Key 文件不支持直接跨账户/数据根搬运。
- 本地模型只允许显式端口的 loopback；云模型必须 HTTPS、公网地址，拒绝重定向、私网解析、代理继承与 URL 内凭据。不放宽应用原有 Host、Origin、Session、CSRF 和数据隔离边界。

## 数据库兼容

新数据库由现有启动器初始化到最新迁移 `0007_add_ai_workflows`。已有数据库不会在普通启动或页面刷新时自动迁移。更新程序后，先保存正文并正常停止旧服务，再双击“启动 AI 网文助手.cmd”启动新版、刷新页面；这一次重启用于加载新版程序。

当前受支持的旧库可直接点击“备份并启用 AI 协作”，无需手动执行 Alembic。页面先保存当前正文，服务再锁定写入、创建并校验数据库备份，然后在同一事务内执行 `0006_add_chapter_manuscript_content` → `0007_add_ai_workflows` 迁移。迁移只增加两张 AI 表，保留正文和历史版本。完成后立即启用当前进程的 AI 服务，可以继续保存模型配置，无需再次重启。

备份保存在当前数据根的 `backups/before-ai-workflow-<唯一标识>.sqlite3`，不会覆盖已有备份；普通双击启动的数据根为 `%LOCALAPPDATA%\AIWebNovel`。备份包含已提交的数据库状态，迁移前会校验完整性和版本。该入口只接受当前数据根管理的数据库，以及结构完整的 `0006` 版本；自定义外部数据库、其他旧版本或结构不匹配会拒绝升级。

正文保存冲突时先处理冲突，再点击启用。备份或迁移失败时不替换原库，迁移事务会回滚并保留已创建的备份；如数据库已升级但 AI 服务启用失败，可以再次点击重试启用，不重复升级或生成备份。其他不支持的情况保留错误信息交给维护者，不删除数据库重试。未启用 AI 时，手动写作仍可使用。

这是作者明确点击触发的专用升级入口；完整备份/恢复向导仍属于 RF-15。开发验证只在自有隔离库进行，不授权开发代理接触正式作者数据。
