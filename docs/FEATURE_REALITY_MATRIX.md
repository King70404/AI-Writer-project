## AI 协作实现（RF-06–10）

已最终 PASS 并通过 [PR #25](https://github.com/King70404/AI-Writer-project/pull/25) 合并：精确候选完整 CI 的后端 2,866 项、前端 693 项、24 个 E2E 场景全部通过，隔离作者流程已验证；SHA、完整结果与边界见已关闭的交付任务 [#24](https://github.com/King70404/AI-Writer-project/issues/24)。

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 模型配置 | 产品内添加/编辑本地或 HTTPS 云模型；Windows DPAPI 加密 Key；可清除 Key | 需自备 OpenAI-compatible 服务；不附送模型或额度 |
| 可解释上下文 | 保存来源版本、纳入理由、截断/省略及实际发送片段；生成前查看 | 固定来源、60,000 字符预算；不是全书记忆或相关性检索 |
| 持久任务与候选 | 保存任务、模型快照、候选和状态；刷新/重启后继续 | 单机单实例；中断请求不自动重发 |
| 作者采纳 | 同一 SQLite 事务写正文修订和幂等回执；校验版本/归属/原选区 | 只有作者确认才能采用；旧候选不能覆盖后续手写 |
| 连续续写 | 每段 200–300 字，采纳后可显式生成下一段，支持暂停/恢复 | 最多 10 次、3,000 字；失败计入步数，不自动重试或自动采纳 |
| 云端发送控制 | 展示上下文、选区、要求及本轮候选；按任务确认发送 | 有次数/字数/token 限制，尚无货币费用硬上限 |

操作、数据兼容与测试入口见 [AI 协作使用与契约](AI_COLLABORATION.md)。新数据根初始化到最新迁移；旧数据库不在普通启动中自动升级，会明确提示先备份再显式升级。开发验证不接触正式作者数据或 Key。

已有单次 AI 接口保留兼容；章节页面使用新的持久协作流程。候选不进入正文或 TXT 导出，只有采纳后的已保存正文才会导出。

## 范文学习与章节规划（当前交付 #28）

| 能力 | 当前实现 | 边界 |
| --- | --- | --- |
| 范文对照分析 | 粘贴并保存，逐句/逐段定位原文，冻结模型和实际请求，明确发送后展示作用、效果、推测理由及迁移方法 | 每份最多 8000 字符/40 个句段；模型输出不完整或引文不匹配会失败，不自动重发；写作意图是推测 |
| 可复用写作方法 | 作者编辑、确认适用条件并保存不可变规则版本；章节明确选用版本 | 分析建议不自动成为正式规则；正文生成不默认发送范文原句 |
| 长篇章节准备 | 持久保存 1–3 个重点、目标字数、冲突、承接/伏笔、排序场景与推进点 | 目标字数是整章计划，当前仍逐段生成与作者采纳；不自动写完整本小说 |
| 关联资料 | 场景选择既有人物，按需关联小说设定，保存发送时来源版本 | 复用已有事实源；独立道具/能力/地点资产库随长篇记忆扩展 |
| 冻结上下文 | 规划、资产和规则进入实际预览，标明截断与省略；后续编辑不影响已准备任务 | 总预算仍 60000 字符，规则/规划/关联资料各自有上限；无全书自动召回 |
| 数据兼容 | 明确备份后从 0006/0007 升级到 0008，保留正文、历史、模型与已有任务 | 普通启动不迁移旧库；开发验证只用隔离数据 |

使用方法见 [范文分析与章节规划](REFERENCE_WRITING.md)。代码和测试证据在 [#28](https://github.com/King70404/AI-Writer-project/issues/28) 汇总，当前最终验证状态以 PLAN 为准。
